# 五模态状态、结果显示与设备热插拔审计

审计日期：2026-10-08  
审计范围：EEG、面部表情、身体姿态、语音情绪、文本情绪；覆盖准备页、问诊/量表实时面板、结果页、设备中途插拔、跨题/跨轮状态以及风险融合。

## 1. 结论

当前实现存在逻辑问题，而且不是单个文案问题。根因是系统把以下四类状态混合在同一个 `status` 或同一张结果卡中：

1. 设备是否存在、是否授权、是否连接；
2. 是否正在采集；
3. 模型是否正在处理、是否得到有效目标；
4. 当前显示的是本轮结果、上一轮结果，还是已过期结果。

因此会出现“设备已断开但旧结果仍像实时结果一样显示”“没有检测到人脸却显示中性 0%”“等待中也显示 0% 置信度”等互相矛盾的界面。

对问题“未检测到摄像头，那是否还在运行”的明确答案是：

- 浏览器没有检测到摄像头、权限被拒绝或视频轨道已结束：面部和姿态的采集应立即停止，模型不能被描述为正在运行；前端应显示“未采集（摄像头未连接/无权限）”，不显示情绪和置信度。
- 摄像头已连接并持续上传，但画面中没有人脸：摄像头采集和人脸检测仍在运行，只是没有有效人脸供情绪分类；前端应显示“摄像头采集中 · 未检测到人脸”，不能显示“中性 0%”。
- 摄像头已连接并持续上传，但画面中没有完整人体：姿态检测仍在运行，但本轮没有有效姿态结果；前端应显示“摄像头采集中 · 未检测到人体”。

## 3. 推荐的统一状态模型

每个模态不能再只用一个 `status`。至少拆成以下字段：

```text
device_state:
  unsupported | permission_required | permission_denied | absent |
  connecting | ready | interrupted | reconnecting

capture_state:
  idle | capturing | recording | paused | interrupted | stopped

processing_state:
  not_requested | collecting | queued | processing | ready |
  no_subject | no_signal | failed | skipped

freshness:
  current_turn | previous_turn | stale

identity/time:
  session_id | turn_id | captured_at | processed_at | last_sample_at
```

还应同时保留两个不同对象：

- `current_result`：只有当前轮、状态有效且未过期的结果；
- `last_valid_result`：仅供历史参考，必须明确标“最近一次结果/上一轮”，不能作为当前结果或直接进入融合。

后端推送的每个模态片段必须保留 `turn_id`。前端收到不属于当前轮的数据时，要么丢弃，要么只放入历史结果区域，不能合并到当前卡片。

## 4. 前端状态显示矩阵

| 场景 | 主文案 | 次文案/动作 | 是否显示置信度 | 是否显示运行动画 |
|---|---|---|---|---|
| 浏览器不支持 | 当前设备不可用 | 更换受支持浏览器 | 否 | 否 |
| 权限未决定 | 等待设备授权 | “允许摄像头/麦克风” | 否 | 否 |
| 权限被拒绝 | 无法访问设备 | “前往浏览器设置允许” | 否 | 否 |
| 没有物理设备 | 未检测到设备 | “连接设备后自动重试” | 否 | 否 |
| 扫描/连接中 | 正在连接 | 显示设备名或扫描状态 | 否 | 仅连接动画 |
| 已连接、未收到样本 | 设备已连接 | 等待有效数据 | 否 | 否 |
| 正在采集 | 正在采集 | 显示样本数/录音时长 | 否 | 是 |
| 正在处理 | 分析中 | 显示处理阶段 | 否 | 是 |
| 无人脸/无人体/无有效信号 | 未检测到有效目标 | 提示调整位置/光线/佩戴 | 否 | 采集可继续，结果动画停止 |
| 当前轮有效结果 | 情绪名称 | 样本数、更新时间 | 是 | 可显示轻量实时标记 |
| 推理失败 | 识别失败 | 错误原因、重试按钮 | 否 | 否 |
| 上一轮结果 | 最近结果：情绪名称 | “上一轮/xx 秒前，本轮未采用” | 可显示，但必须灰化 | 否 |
| 数据过期或网络断开 | 实时数据已中断 | 保留最后更新时间、自动重连 | 历史值只能灰化 | 否 |
| 本轮主动跳过 | 本轮未采集 | 说明原因，例如点击作答、未录音 | 否 | 否 |

关键显示规则：没有结果时不应显示 `0% 置信度`。应显示 `—` 或直接隐藏整行。`0%` 只在模型确实输出了合法的零概率时才成立。

## 5. 五个模态分别应该怎样工作

### 5.1 面部表情

- 依赖：摄像头权限、视频轨道、帧上传服务、人脸检测、表情模型。
- 摄像头不存在时：`device_state=absent`、`capture_state=stopped`、`processing_state=not_requested`。
- 摄像头存在但无人脸时：`device_state=ready`、`capture_state=capturing`、`processing_state=no_subject`。
- 无人脸不是“中性”，也不是一次置信度为 0 的分类。
- 只有检测到人脸并完成分类后，才显示情绪和置信度。

### 5.2 身体姿态

- 与面部共享摄像头设备，但采集/推理状态应分别维护；人脸有效不等于人体有效。
- 累积帧不足时显示“正在收集姿态序列（n/N）”，不能保留上一轮标签冒充当前结果。
- 无人体时显示“未检测到完整人体”，并给出“后退一些、确保上半身/全身入镜”的操作提示。
- 摄像头中断或长时间后台挂起后，要清空姿态时序缓存；不能把断线前后的帧拼成一个序列推理。

### 5.3 语音情绪

- 依赖：麦克风、完整录音段、音频解码和语音情绪模型；它与 ASR/文本情绪应解耦。
- 正在录音只显示时长和音量/采集状态；结束后显示“语音分析中”。
- 麦克风中途拔出必须进入“录音被中断”，默认丢弃该不完整段并要求重录，不能自动按正常完成提交。
- 即使 ASR 没有文字，语音情绪仍可能有独立结果；界面需分别反映，不应把文本失败等同于语音失败。

### 5.4 文本情绪

- 文本不是物理设备模态，其输入来自 ASR 转写或用户文字输入。
- 无有效转写时显示“未生成文本（无有效语音转写）”，不是永久“等待中”。
- 用户点击选项而没有录音时，应标为 `skipped`，而不是 0% 或 pending。
- 文本结果必须绑定当前 `turn_id` 和实际转写文本，避免上一题文本结果残留。

### 5.5 EEG

- 依赖：服务启用、运行时依赖、蓝牙/数据源、设备连接、有效数据包、完整推理窗口、模型。
- `scanning`、`connecting`、`connected`、`streaming` 必须分开；`connected` 不等于已经收到有效 EEG 数据。
- 断开时立即冻结并灰化波形，标“设备已断开，正在重连”；旧结果只能作为历史显示。
- 重连后收到首个新数据包才进入“采集中”，并从新的干净窗口开始。断连前不完整窗口应丢弃，避免跨断点拼接。
- 目前 BLE 服务端已有循环扫描和自动重连能力，但 UI 没有正确呈现这一过程。

## 6. 设备中途插拔的推荐流程

### 摄像头拔出

1. 监听 `MediaStreamTrack.onended`、`mute/unmute` 和 `navigator.mediaDevices.devicechange`。
2. 立即设置 `cameraReady=false`，清空视频 `srcObject`，停止帧抓取定时器。
3. 面部与姿态卡进入 `interrupted`；当前轮结果失效，旧结果移到“最近结果”并灰化。
4. 通知后端产生 capture-gap 事件，并清空姿态时序缓存。
5. 显示“摄像头已断开，连接后自动恢复”。

### 摄像头插入

1. `devicechange` 后去抖重新枚举设备。
2. 权限已授予时自动重新 `getUserMedia`；若浏览器要求用户手势，则显示“启用摄像头”按钮。
3. 获得视频轨道后先显示“已连接，正在验证画面”。
4. 第一帧成功上传后才进入“采集中”；姿态序列从零开始。
5. 第一份属于当前轮的有效推理返回后才显示情绪结果。

### 麦克风拔出/插入

- 拔出：终止录音并标“录音被中断”，不要触发正常 `onRecordingComplete`；清除不完整音频或由用户明确选择是否保留。
- 插入：更新为“麦克风可用”；下一次录音重新申请新 stream。若当前回答被中断，显示“重新录制”。

### EEG 拔出/插入

- 拔出：服务端保持自动扫描，但前端显示“已断开/正在重连”；停止实时光效，旧波形和结果灰化；废弃不完整推理窗口。
- 插入：扫描、连接、等待首包、采集中逐级显示；收到首包后重置波形时间轴，从新的窗口推理。

### 网络或推理服务中断

- SSE/HTTP 中断后按 `last_updated_at` 启动过期计时；超过阈值即标 `stale`。
- 不清空历史结果，但停止所有“实时运行”的绿色圆点和脉冲动画。
- 自动重连成功后，只接受当前 session/turn 且时间更新的数据。

## 7. 推荐实施顺序

### 第一阶段：先消除误导和错误融合

1. 修复 `no_face`、`no_pose`，将其建模为 `no_subject`，主标签和分数必须为空。
2. 卡片仅在 `processing_state=ready` 且结果属于当前轮时显示置信度。
3. 所有模态保留并校验 `turn_id`；跨题时当前结果清空，历史结果单独显示。
4. 风险服务纳入前校验状态、新鲜度、轮次和有效样本数。
5. 把 EEG 负向中文标签乱码修正为“消极”。

### 第二阶段：实现真正的热插拔

1. 为摄像头/麦克风建立统一的 `MediaDeviceMonitor`。
2. 监听 `devicechange` 和每条 track 的生命周期，支持自动重获 stream。
3. 麦克风中断不再自动提交残缺录音。
4. 摄像头/EEG 断点触发后端时序缓存重置。

### 第三阶段：补齐可观察性和结果解释

1. 每张卡展示设备、采集、处理、新鲜度四层状态中的必要信息。
2. 展示最后成功采样时间、当前样本数和错误原因。
3. 最终报告显示“本次五模态覆盖 3/5”，列出每个模态是已采用、质量不足、未连接、失败还是跳过。
4. 最终报告文案改为条件式，不能在数据缺失时仍宣称“五模态均已综合”。

## 8. 必须覆盖的验收测试

1. 首次进入时没有摄像头；进入后插入；恢复采集且不刷新页面。
2. 正常采集中拔掉摄像头；1 秒内停止上传并清除“已接入”状态。
3. 摄像头可用但画面无人；显示“未检测到人脸/人体”，不显示中性或 0%。
4. 摄像头断开 10 秒后重新接入；姿态序列不跨断点拼接。
5. 拒绝摄像头/麦克风权限，再从浏览器设置中允许；页面可恢复。
6. 录音中拔掉麦克风；不上传残缺音频，语音/文本均显示明确中断状态。
7. 完成上一题后进入下一题；五张卡均不能把上一题结果当作当前结果。
8. SSE 断线但页面仍在；超过新鲜度阈值后结果自动灰化并标“数据中断”。
9. EEG 未连接、扫描中、已连接无首包、流式采集、推理中、结果就绪、断开重连分别显示正确。
10. EEG 断开后重连；新推理窗口不包含断开前残余帧。
11. 点击量表选项但不录音；语音和文本显示“本轮未采集/已跳过”，不永久等待。
12. 最终报告只纳入当前会话中有效且通过质量门槛的模态，并准确显示覆盖率。

## 9. 本轮审计边界

本报告是代码级逻辑审计，没有在本轮直接修改运行代码。结论来自当前工作区源码；浏览器、摄像头、麦克风和 EEG 实机热插拔仍应按上面的验收矩阵执行端到端测试。
