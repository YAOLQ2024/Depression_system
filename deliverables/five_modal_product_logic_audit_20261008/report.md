# 五模态产品逻辑与最小必修闭环报告

审计日期：2026-10-08  
审计对象：EEG、面部表情、身体姿态、语音情绪、文本情绪  
审计视角：产品真实性、用户理解、异常恢复、结果可信度和最终风险融合

## 1. 产品结论

当前问题不是单纯的状态文案或界面展示问题，而是产品没有统一定义：

- 模态是否具备输入条件；
- 是否真的正在采集；
- 模型是否得到本轮有效结果；
- 当前显示的是本轮数据、历史数据还是过期数据；
- 该模态最终是否被纳入风险评估。

这会产生一个严重的产品错觉：界面看起来五个模态都在工作，但实际可能存在设备未连接、没有有效目标、结果属于上一题、数据已经过期，甚至残缺录音仍被提交分析等情况。

在心理健康评估场景中，系统首先要保证“状态真实”和“结果来源可解释”，其次才是界面连续性和视觉效果。当前版本不适合在未修复核心状态链条前对外宣称“完整五模态实时评估”。

## 2. 五模态在产品中的正确定位

| 模态 | 输入来源 | 关键依赖 | 产品属性 |
|---|---|---|---|
| EEG | 脑电数据流 | EEG 设备、连接、有效数据包、完整窗口 | 外部设备模态 |
| 面部表情 | 视频帧 | 摄像头、权限、人脸入镜 | 摄像头单帧模态 |
| 身体姿态 | 连续视频帧 | 摄像头、完整人体、连续时序 | 摄像头时序模态 |
| 语音情绪 | 完整录音段 | 麦克风、权限、音频完整性 | 麦克风模态 |
| 文本情绪 | 转写文字或文字输入 | ASR 有效转写或用户文本 | 派生模态，不是设备模态 |

“五模态系统”不等于“五个模态在每一轮都有效”。产品必须展示实际覆盖情况，例如：

> 本轮有效模态：3/5  
> 已采用：面部、语音、文本  
> 未采用：EEG 未连接、姿态未检测到完整人体

## 3. 当前最主要的产品逻辑问题

### 3.1 没有输入被错误表达成情绪结果

当前可能出现：

- 未检测到人脸，却显示“中性 0%”；
- 未检测到人体，却显示“情绪待识别 0%”；
- 尚未完成推理，却显示“等待中 0%”。

产品规则必须改为：

- 无输入：不显示情绪、不显示置信度；
- 输入无效：说明无效原因，并给出调整方法；
- 模型有效输出“中性”：才允许显示中性和对应置信度。

### 3.2 设备状态与模型状态混在一起

“摄像头未连接”和“摄像头已连接但没有人脸”是完全不同的状态：

- 摄像头未连接：采集没有运行，面部和姿态模型没有新输入；
- 摄像头已连接但无人脸：视频采集和人脸检测仍在运行，但没有进入有效情绪分类；
- 摄像头已连接且有人脸：完成分类后才存在情绪结果。

如果不分开，用户无法判断设备问题、姿势问题还是模型问题，也不知道该执行什么操作。

### 3.3 历史结果冒充当前结果

当前为了避免切换题目时结果卡闪回等待状态，会保留上一轮结果。但界面没有标注其历史身份，用户会认为它仍是本轮实时结果。

产品原则应当是：

- 当前轮没有有效结果时，当前结果区域为空；
- 上一轮结果可以保留，但必须显示为灰色“上一轮结果”；
- 上一轮结果不能自动参与当前轮融合；
- 真实性优先于界面不闪烁。

### 3.4 设备中断后缺少可恢复流程

当前摄像头只在进入页面时初始化一次，中途拔出后状态可能不更新，中途插入后也不能自动恢复。用户只能刷新页面，而刷新又可能影响当前问诊进度。

麦克风中途断开更严重：残缺录音可能被当作正常完成的回答提交，继而生成语音和文本结果。

EEG 服务端具备自动扫描和重连能力，但前端没有把“扫描、连接、等待首包、采集中、断开重连”准确呈现出来。

### 3.5 最终报告没有披露数据覆盖情况

如果结果页笼统写“已综合多模态信息”，用户会自然理解为五个模态都参与了评估。产品必须明确展示：

- 哪些模态已纳入；
- 哪些模态未纳入；
- 未纳入原因；
- 有效样本数和质量是否达到要求。

### 3.6 风险融合缺少有效性门槛

风险融合不能只检查“有没有分数”，还必须检查：

- 是否属于当前会话和当前轮；
- 模态状态是否为有效完成；
- 数据是否已经过期；
- 样本量和质量是否达标；
- 是否是设备中断前的残留结果。

否则前端即使显示正确，后端仍可能把旧数据或无效数据纳入最终风险。

## 4. 产品状态定义

每个模态至少需要表达以下四层状态：

### 4.1 设备状态

```text
不支持 / 待授权 / 权限拒绝 / 未检测到设备 /
连接中 / 已连接 / 已中断 / 重连中
```

文本模态没有物理设备，设备状态应显示为“不适用”，不能复用麦克风状态。

### 4.2 采集状态

```text
待命 / 采集中 / 录音中 / 已中断 / 已停止
```

### 4.3 处理状态

```text
未请求 / 收集中 / 排队中 / 分析中 / 有效结果 /
未检测到目标 / 无有效信号 / 失败 / 已跳过
```

### 4.4 数据归属和新鲜度

```text
当前轮 / 上一轮 / 已过期
```

每份结果必须携带 `session_id`、`turn_id`、采样时间和处理时间。前端不能仅通过“最近收到的数据”推断其属于当前问题。

## 5. 页面级产品方案

### 5.1 准备页

准备页需要回答三个问题：

1. 设备是否存在并获得权限；
2. 是否真的收到有效输入；
3. 如果不可用，会影响哪些模态。

建议提供：

- “重新检测设备”；
- “前往浏览器设置”；
- “继续基础评估”。

除非业务或临床协议明确要求，不建议因为增强模态缺失而完全阻断问诊。可以继续完成基础问诊和量表，但必须明确降低模态覆盖率。

### 5.2 实时问诊页

页面顶部展示：

> 当前有效模态 3/5 · 摄像头已断开 · 正在自动重连

单张模态卡只应显示：

- 当前状态；
- 当前轮有效结果；
- 必要的恢复操作。

没有有效结果时隐藏置信度，不能用 `0%` 代替空值。

### 5.3 最终结果页

增加“五模态数据完整性”模块：

| 模态 | 本次状态 | 是否纳入 | 原因 |
|---|---|---:|---|
| EEG | 未连接 | 否 | 未收到有效数据 |
| 面部 | 有效 | 是 | 当前会话有效样本达标 |
| 姿态 | 质量不足 | 否 | 未检测到完整人体 |
| 语音 | 有效 | 是 | 完整录音分析完成 |
| 文本 | 有效 | 是 | 当前回答转写有效 |

结果页应使用条件式文案：

> 本次评估综合了问诊、量表及 3 项有效模态信息。EEG 和姿态未纳入本次评估。

## 6. 中途插拔的产品行为

### 摄像头拔出

1. 立即关闭实时预览和运行标识；
2. 面部、姿态进入“采集中断”；
3. 当前结果失效，历史结果灰化；
4. 停止上传视频帧；
5. 显示“连接后自动恢复”。

### 摄像头插入

状态必须依次变化：

```text
检测到设备 → 正在连接 → 正在验证画面 → 正在采集 → 本轮结果就绪
```

插入设备不等于已有有效画面，连接成功也不等于模型已经有结果。

### 麦克风中断

- 当前录音进入“录音被中断”；
- 默认不提交残缺音频；
- 语音和文本不能生成正式结果；
- 重新连接后提供“重新录制”。

### EEG 中断与恢复

- 断开后停止波形滚动和实时动画；
- 旧波形、旧结果灰化；
- 不完整推理窗口作废；
- 恢复连接后等待首个新数据包；
- 使用新的完整窗口重新推理。

### 网络或推理服务中断

设备中断和服务中断必须使用不同文案。服务中断时保留最后结果供参考，但标记为“数据已过期”，并停止实时状态动画。

## 7. 优先级建议

### P0：上线前必须完成

1. 无人脸、无人体、无数据不再生成情绪占位结果；
2. 没有有效结果时不显示 `0% 置信度`；
3. 当前轮结果与上一轮结果完全分离；
4. 麦克风异常中断不提交残缺录音；
5. 风险融合排除失败、过期、错误轮次和质量不达标的数据；
6. 修复 EEG 中文负向标签乱码；
7. 最终报告披露实际模态覆盖率。

### P1：随后完成

1. 摄像头和麦克风热插拔；
2. EEG 重连状态可视化；
3. 设备、采集、处理、新鲜度状态拆分；
4. 摄像头或 EEG 中断后重置时序缓存；
5. 补充重新授权、重新检测和重新录制入口。

### P2：体验增强

1. 多摄像头、多麦克风切换；
2. 光线、构图、人体入镜质量引导；
3. 管理端模态可用率和异常率统计；
4. 报告完整性评分与长期趋势。

## 8. 产品验收标准

1. 设备拔出后，界面必须在约 1 秒内停止显示正在运行；
2. 设备重新插入后，无需刷新页面即可恢复；
3. 没有有效输入时不显示情绪和置信度；
4. 每个当前结果都能证明属于当前会话和当前轮；
5. 历史结果有明确标识，且不参与当前轮融合；
6. 录音中断不会产生正式语音或文本结果；
7. EEG 断连前后的数据不会被拼接为同一个推理窗口；
8. 最终报告展示实际参与模态和未参与原因；
9. 风险融合结果只使用状态、轮次、新鲜度和质量均有效的数据。

## 9. 最小、必须优化的逻辑链条

如果第一阶段不做完整状态系统重构，至少必须打通下面这条最小闭环：

```text
设备/输入是否可用
        ↓
是否获得当前轮有效样本
        ↓
模型是否完成且输出有效
        ↓
结果是否属于当前 session + turn
        ↓
结果是否未过期且质量达标
        ↓
前端才显示情绪与置信度
        ↓
风险服务才允许纳入融合
        ↓
结果页披露实际纳入情况
```

对应的最小代码与产品改动只有七项：

### 必修 1：无效输入不产生情绪结果

`no_face`、`no_pose`、无 EEG 信号、无有效转写必须返回空标签和空分数，并保留明确原因码。禁止使用“中性 0%”作为占位。

### 必修 2：结果必须绑定当前轮

五个模态的实时数据都保留 `session_id` 和 `turn_id`。切换问题时当前结果立即失效；上一轮数据只能进入历史区域。

### 必修 3：前端建立唯一的结果显示门槛

只有同时满足以下条件才显示情绪和置信度：

```text
processing_status == ready
AND result.turn_id == current_turn_id
AND result 未过期
AND result 通过质量门槛
```

其他状态统一显示原因和恢复操作，不显示 `0%`。

### 必修 4：异常中断立即终止当前采集

摄像头、麦克风或 EEG 中断后，立即停止对应采集状态。麦克风中断不得触发正常录音完成回调；姿态和 EEG 的不完整时序窗口必须清空。

### 必修 5：至少支持自动重新检测

监听设备变化和媒体轨道结束。设备重新出现后自动尝试恢复；如果浏览器要求用户操作，则显示明确的“重新启用”按钮。不能要求用户刷新整个问诊页面。

### 必修 6：风险融合设置同一套准入门槛

风险服务必须再次校验状态、轮次、新鲜度、质量和有效样本数，不能信任前端展示，也不能仅因为存在分数字段就纳入计算。

### 必修 7：最终结果披露模态覆盖率

结果页至少显示“本次采用 N/5 个模态”，并列出未采用原因。没有这一项，就不能对外使用“五模态综合完成”之类的绝对表述。

完成以上七项后，可以暂时不做复杂的设备切换界面、管理端统计和高级质量提示，但系统已经形成最小可信闭环：无效输入不会伪装成结果，旧结果不会串入当前轮，异常数据不会进入风险融合，用户也能知道本次评估到底使用了哪些信息。
