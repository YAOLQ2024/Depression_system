# 患者端竖屏触摸一体机改造方案

状态：2026-10-07 已按本方案完成患者端响应式实现和浏览器回归。具体技术依据见 [调研与架构](portrait/01-research-and-architecture.md)，逐页现状与交互设计见 [页面清单](portrait/02-screen-inventory-and-design.md)，验证口径见 [实施与验收](portrait/03-implementation-and-acceptance.md)。55 英寸设备触摸、权限和 kiosk 验收仍需在设备现场完成。

## 1. 文档目的

本文定义患者端在竖屏触摸一体机上的适配目标、页面范围、交互原则、实施顺序与验收口径。先明确前端适配边界；问诊、量表、风险评估与干预业务规则仍由现有后端服务负责。

## 2. 目标设备与使用方式

| 项目 | 目标 |
| --- | --- |
| 设备 | 优视达 55 英寸立式红外触摸一体机，型号 USD55 |
| 屏幕方向与比例 | 竖屏，9:16 |
| 分辨率 | 1080 × 1920 |
| 刷新率 | 60 Hz |
| 操作方式 | 患者直接触摸屏幕 |
| 展示方式 | 患者端应用全屏运行，演示流程不显示浏览器工具栏 |

显示器方向由操作系统或设备配置设为竖屏。浏览器通过全屏或 kiosk 启动方式占满屏幕；网页根据浏览器实际视口排版，不旋转页面，也不通过拉伸横屏布局来填满屏幕。触摸坐标方向需在设备完成旋转后校准。

## 3. 改造目标与边界

### 3.1 目标

- 让患者从进入系统开始，可以在一台竖屏设备上完成整套演示流程：登录、问诊准备、数字人问诊、量表、结果查看和干预。
- 在触摸操作和较远距离阅读的条件下，保证主要信息清楚、主操作容易找到。
- 支持流程中断后的继续入口、页面返回和错误恢复，不因竖屏布局破坏现有状态流转。
- 让患者端继续适配常规横屏浏览器；竖屏改造不改变现有 API 契约和后端业务语义。

### 3.2 不在本方案范围内

- 不改问诊状态机、量表计分、风险分层、干预推荐或数据模型。
- 不让网页自行强制浏览器进入全屏。浏览器全屏 / kiosk 由设备端运行配置负责。
- 不把后台 `operations-console` 纳入本次患者端改造。
- 不新增患者自助建档、匿名模式或绕过现有身份与授权流程的入口。

## 4. 页面范围与竖屏布局建议

患者端路由定义见 `apps/consultation/client/src/routes.ts`。本次覆盖正式患者流程页面；实验室播放器演示页不纳入正式流程验收。

| 流程阶段 | 页面 / 路由 | 竖屏布局与交互重点 |
| --- | --- | --- |
| 进入系统 | 封面 `/`、登录 `/login` | 标题、说明和登录表单纵向排列；输入框与提交按钮适合触摸；登录错误在表单附近清晰呈现。 |
| 患者首页 | `/home` | 将“开始 / 继续问诊”作为首要入口；历史、档案和干预作为次级入口纵向排列；避免依赖横向分栏或环绕式导航完成主流程。 |
| 资料与问诊准备 | `/profile`、`/preparation` | 表单按步骤纵向排列；长内容允许滚动；设备状态、授权和知情确认结果清楚可见；当前步骤与下一步操作明确。 |
| 数字人问诊 | `/consultation` | 视频保留素材原始宽高比并置于主要视觉区；问题 / 字幕、录音或回答控件、进度按纵向阅读顺序排列。多模态状态与调试性信息收进可展开区域，避免遮挡患者操作。 |
| 量表选择与作答 | `/scale-selection`、`/scale-questionnaire` | 量表卡片单列；答题页一次聚焦当前题目，选项使用大触摸区域；题目、进度和前进 / 返回关系清楚。 |
| 评估结果 | `/result` | 首屏优先显示本次结果摘要及后续操作；趋势、量表详情和咨询摘要采用纵向内容或抽屉 / 分层查看，避免多个窄列并排。 |
| 干预体验 | `/intervention`、`/intervention/video`、`/intervention/game`、`/intervention/story` | 视频保持合适比例；游戏和故事控件按触摸操作重排；播放、暂停、继续和退出等操作在竖屏中始终可达。 |
| 历史回顾 | `/history`、`/history/:id`、`/history/:id/scale/:scaleId` | 记录列表单列展示，重要状态和日期易读；详情采用纵向阅读，不要求横向滚动。 |

问诊过程中的暂停、风险提示、设备未就绪、加载失败和断线恢复等状态，应沿用现有业务状态并为竖屏提供完整呈现；不能只适配成功路径。

## 5. 交互与视觉约束

### 5.1 触摸操作

- 可触摸控件建议至少达到 48 × 48 CSS px；关键主操作可更大，并留出足够间距，降低误触。
- 操作状态要有明显反馈：按下、处理中、成功、不可用和错误状态均可辨认。
- 不将悬停作为发现按钮、提示或完成操作的唯一方式。
- 固定底部操作区需为滚动内容预留空间，并避开系统边缘；不能覆盖题目、视频字幕或最后一项选项。
- 页面中主要按钮应处于患者实际可触及范围。设备安装高度尚未提供，需在实机摆放后检查顶部和底部操作是否都方便触达。

### 5.2 阅读与内容密度

- 以单列信息层级为主，避免把桌面双栏压缩成窄列。
- 标题、题目、正文和辅助说明形成清楚的字号层级；重要说明不只依赖颜色表达。
- 图表优先使用足够宽度；信息较多时分段或按需展开，不强行缩小到难以阅读。
- 视频维持素材比例。容器可随可用空间调整，但不得裁掉关键人物、文字或控制区域。

### 5.3 全屏与视口

- 响应式布局按浏览器报告的视口宽高工作；OS 显示缩放会影响 CSS 像素，因此不能只按物理分辨率硬编码组件尺寸。
- 竖屏模式使用适合长内容的页面滚动；问诊 / 答题等沉浸环节可采用受控分区，但需确保主要操作和内容不会被 `overflow: hidden` 裁切。
- 适配时检查 `100dvh` / `100vh`、顶部栏高度、底部操作区和滚动容器之间的关系。现有布局使用满屏容器与内部滚动，需逐页确认，而非只调整全局断点。
- 通过方向和实际可用宽度共同适配。布局不能假设所有设备缩放设置下 CSS 视口恒为 1080 × 1920。

## 6. 前端实施建议

### 阶段 0：现状盘点与设计基线

1. 对照路由清点各页面的桌面布局、独立滚动区域、固定定位元素、视频比例和流程状态。
2. 用目标设备尺寸建立竖屏页面线框，先确认主链顺序和各页面主操作位置。
3. 明确设备登录方式、演示账号、开机启动方式、OS 缩放和触摸坐标校准方式；这些由部署环境提供，不写入患者端业务逻辑。

**产出：** 页面清单、竖屏线框 / 页面规格、设备启动与全屏配置说明。

### 阶段 1：共享竖屏布局基础

1. 建立患者端统一的竖屏页面容器、内容宽度、间距、字号和触摸控件规则。
2. 梳理 `MainLayout` 与 `ConsultationLayout` 的高度、滚动和页头行为，减少各页面重复补丁。
3. 明确首页导航、流程内返回、底部主操作与内容滚动之间的统一规则。
4. 保留横屏布局，通过响应式样式切换布局，不复制一套业务页面或 API 调用。

**产出：** 可复用的竖屏布局约定与基础样式。

### 阶段 2：按主流程改造页面

建议依次实现：

1. 登录、首页、资料 / 问诊准备。
2. 数字人问诊和异常 / 暂停状态。
3. 量表选择、量表作答和恢复流程。
4. 结果摘要、详情查看和干预入口。
5. 视频、游戏、故事干预及历史记录页面。

每页只调整前端呈现和交互布局；流程状态继续来自现有上下文与服务响应。

### 阶段 3：实机走查与部署配置

1. 在 USD55 竖屏、全屏浏览器状态下，从登录开始走完一轮演示流程。
2. 用实际触摸检查主操作、选项、返回、视频控件、长页滚动和抽屉关闭区域。
3. 检查设备授权、加载失败、问诊暂停、断线恢复和会话继续等状态。
4. 单独配置并记录浏览器 kiosk / 全屏启动和触摸方向校准；确认退出 kiosk 的维护方式。

**产出：** 实机走查记录、全屏启动配置和需修复问题清单。

## 7. 验收标准

### 7.1 设备与显示

- USD55 已由系统设置为竖屏；浏览器全屏 / kiosk 后患者端占满屏幕，没有浏览器工具栏遮挡。
- 页面使用 9:16 视口正常排版；无横向滚动条、关键内容裁切或页面整体旋转变形。
- 触摸坐标与屏幕方向一致；关键触摸控件可触达，操作后有清楚反馈。
- 60Hz 下页面滚动、状态切换和已有动画显示正常；视频不变形、不遮挡核心控件。

### 7.2 患者全流程

- 可以从登录进入首页，完成准备，进入数字人问诊、量表选择和作答、结果查看及干预体验。
- 中断后能通过现有继续入口回到正确阶段；返回、刷新、加载和异常状态不会造成页面控件不可见。
- 首页、结果页、详情、干预和历史页面的主要操作均可通过触摸完成。
- 问诊与量表中的字幕 / 题目、进度和回答控件在竖屏下不会互相遮挡。
- 横屏浏览器的既有患者端布局不因本次样式改动而退化。

### 7.3 临床与数据边界

- 不改变会话状态机、API 契约、量表答案、评分结果和后端风险 / 干预逻辑。
- 错误、风险、暂停和设备未就绪提示仍能准确表达服务状态，不因竖屏改造而隐藏或简化成误导性文案。

## 8. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 大屏物理尺寸与 OS 缩放使 CSS 视口和预期不同 | 以浏览器实际视口排版，实机验证字体、卡片密度和触摸区域。 |
| 55 英寸屏幕安装高度未知，顶部 / 底部操作不易触及 | 在最终安装位置走查触达范围，必要时让关键动作靠近屏幕中部或采用可滚动步骤。 |
| 现有满屏布局和内部 `overflow-hidden` 导致内容被裁切 | 逐页梳理滚动所有权；长内容允许页面滚动，固定操作栏预留安全空间。 |
| 视频、字幕、摄像头预览和采集状态争用空间 | 明确主视觉与主操作优先级；次要状态折叠；保持视频比例并实机观察可读性。 |
| 浏览器全屏设置与患者端前端职责混淆 | 将 kiosk / 开机启动作为设备部署配置单独记录；网页不尝试自动绕过浏览器全屏限制。 |
| 横屏与竖屏规则相互覆盖 | 共用业务页面，集中管理响应式布局规则，并在两类视口分别检查。 |

## 10. 当前决策与待设备现场确认项

已确认：

- 目标应用为患者端 `consultation`。
- 目标是整套患者流程，而非单个展示页。
- 目标设备为 USD55，竖屏 1080 × 1920、9:16、60Hz、55 英寸红外触摸一体机。
- 演示时应用始终全屏显示。

需在设备部署或实机走查时确认：

- Windows / 设备系统的显示缩放比例与浏览器实际 CSS 视口。
- 一体机实际安装高度和患者可触达区域。
- 浏览器 kiosk 启动方式、演示账号准备和维护退出方式。
- 屏幕旋转后的红外触摸坐标是否已校准。
