# Step 7：统一回退策略与扩展点

## 变更目标

把“preview/commit 不一致”“后台预热失败”“节点无视频资源”这三类回退场景收口到共享 VideoNode 内核，不让咨询页和量表页继续各自长出例外逻辑。

## 本次落点

1. 共享 controller 增补回退时序：
   - `commit_mismatch`
   - `preload_failed`
2. 共享 controller 新增 `handleClipLoadError(...)`
   - 如果失败的是后台预热节点，丢弃预热结果
   - 当前前台节点继续保持业务正确性
3. 共享 controller 的正式提交现在会校验：
   - 如果 preview 的下一节点与正式 commit 返回不一致
   - 立即丢弃旧预热结果，按正式结果重新切换
4. 新增共享缺视频回退规则：
   - `manual_commit`
   - `local_skip`
   - `allow_response`
5. 两个页面只消费共享回退规则：
   - 咨询页：自动系统题缺视频时允许手动继续到下一题
   - 量表页：阶段引导缺视频时本地跳过；题目缺视频时直接放行为文字题

## 当前效果

- consultation 和 assessment 都会用同一套规则处理预热失败与 commit mismatch。
- 后台预热视频加载失败时，不会再误判成“当前前台视频彻底不可用”。
- 新节点如果没视频资源，也不会直接卡死主流程，而是按共享 fallback 行为降级。

## 对照完成标准

- 咨询和量表两端都走同一套 fallback 原则：已满足
- 新增视频节点的需求文档可以直接引用本设计，不再另起播放器方案：已满足前提，规则已收口到共享 `video-node/`
- 代码结构上已经能看出“共享内核 + 会话适配器”的边界：已满足
