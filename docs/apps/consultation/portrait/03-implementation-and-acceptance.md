# 竖屏实施顺序与验收规约

状态：2026-10-07。本文是实施检查清单，页面决定见 [逐页设计](02-screen-inventory-and-design.md)，技术路线见 [调研与架构](01-research-and-architecture.md)。

## 实施顺序

1. 删除纯前端 Demo 路由与资源，确认不会触及问诊业务或现有启动脚本。
2. 建立独立竖屏样式入口、页面语义标识及共享字号、间距、按钮尺寸、滚动约束。
3. 先完成入口、首页、档案、准备，再完成问诊、量表选择和作答；每一步均在 1080 × 1920 浏览器看真实页面。
4. 完成结果、干预四页、历史三页和共享弹层；核对每个正式路由。
5. 自动检查 TypeScript、构建和主操作可见性；对 1920 × 1080 横屏做截图回归。再在实机检查触摸、摄像头、麦克风、音频与 kiosk。

## 浏览器验收矩阵

| 情况 | 检查 |
| --- | --- |
| 1920 × 1080 横屏 | 现有布局、大小、定位、交互与基线一致；不出现竖屏专属卡片和菜单。 |
| 1080 × 1920 竖屏 | 所有正式路由无水平溢出；主操作可见或随纵向滚动可到达；无内容/按钮互遮。 |
| 900 × 1600、768 × 1024 竖屏 | 缩放和比例变化时内容仍能重排；表单、弹窗、图表可完整阅读。 |
| 390 × 844 竖屏 | 最小视口安全退化，允许纵向滚动；触摸目标不溢出。 |
| 键盘/输入 | 输入聚焦后表单可滚动到提交按钮；不因方向媒体查询切换丢失输入状态。 |
| 错误/恢复 | 加载、空数据、未授权、摄像头不可用、问诊暂停、网络错误、继续会话等状态内容完整。 |

## 可执行验收标准

- 正式患者路由与横屏相同，Demo 无法访问；没有复制问诊/量表业务组件。
- 页面级和内部滚动容器的 `scrollWidth <= clientWidth + 1`；对使用 `overflow:hidden` 的页面另查主按钮、题目与风险文案矩形是否位于可见或可滚动区域，不能仅凭无横向滚动条判定合格。
- 关键按钮在目标视口至少 56 CSS px 高；普通触摸控件至少 48 CSS px，间距足以避免误触。例外需逐项记录。
- 视频不变形，主要播放/暂停/全屏按钮在竖屏可达；游戏 iframe 的输入、帮助弹窗和返回入口可操作。
- 问诊和量表的摄像头状态、字幕、当前问题、回答控件、风险提示互不遮挡；语音和点击答题功能维持。
- 横屏前后相同页面相同状态的截图经人工对照，无布局回归；必要时用像素差异定位变更。
- `npm run typecheck` 和 `npm run build` 通过，浏览器无新增运行错误。
- 55 英寸实机的最终通过需要实际安装高度、Windows 缩放、红外校准、设备权限、音视频播放验证；桌面模拟截图不能代替这一项。

## 数据与截图

- 浏览器审查使用 Docker 开发环境的现有演示账号和已有会话，不提交新的量表答案或修改评分、风险结果；打开干预页或节目可能按原有逻辑写入体验事件。量表选择的状态夹具仅拦截浏览器收到的响应。
- 包含姓名、问答或健康信息的截图只放在本机 Codex 可视化目录，不进 Git，不发布。
- 若用自动截图脚本复测，先验证会话状态和页面 URL，避免把路由重定向或加载页误记为目标页。
