# 患者端横竖屏共存：调研与技术决策

状态：2026-10-07 已完成调研与代码、实屏基线审查。适用范围为 `apps/consultation/client`，目标设备为 55 英寸 1080 × 1920 竖屏红外触摸一体机。

## 决策

**保留一套路由、组件和业务状态，用响应式布局针对可用空间重排。** 横屏现有版是基线，竖屏规则集中在独立样式层，并限制在 `(orientation: portrait)`。页面中的内容层级、触摸动作和滚动归属按页面设计，不能把整张横屏画布旋转、缩放，也不能把同一套问诊与量表业务复制成第二套页面。

这项决策的依据是：

1. [web.dev 响应式设计指南](https://web.dev/articles/responsive-web-design-basics)建议按内容决定断点，使用 Grid/Flex 重排，适配触摸输入，避免水平滚动。
2. [MDN 媒体查询指南](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries)支持按视口宽高、比例、方向和输入能力选择布局；组件局部还可使用[容器查询](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)。
3. [MDN orientation 说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/orientation)中的方向是**浏览器视口**方向，不保证等于物理设备方向。软键盘或窗口尺寸变化也可能使它改变。因此页面应同时检查实际宽高、内容可用空间和滚动结果，不能以机型或物理像素硬编码。
4. [WCAG 2.2 目标尺寸最低要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)是 24 × 24 CSS px，且有间距等例外。本项目面向站立触摸，设计目标提高到主操作 56 px、普通操作 48 px；这两个值是本项目的人机工学目标，并非 WCAG 强制值。

## 方案比较

| 方案 | 优点 | 对本系统的问题 | 结论 |
| --- | --- | --- | --- |
| 整页旋转或等比缩小横屏 UI | 改动少 | 字幕、量表、风险提示和按钮被压小；触摸坐标与阅读方向难处理 | 不采用 |
| 独立的竖屏 Demo/第二套页面 | 短期展示快 | 问诊状态、恢复、错误、量表计分和风险提示容易分叉；维护两套页面 | 已删除原 Demo，不采用 |
| 单页双布局，媒体查询 + 少量语义化组件重排 | 业务逻辑共用；可按页面控制视觉层级；横屏规则可隔离 | 需要逐页检查定位、滚动和弹层 | **采用** |

## 工程约束

- 使用原路由与原 API。仅改变前端布局、操作可达性、响应式媒体尺寸，不改变量表计分或风险判定。
- 横屏 CSS 保持既有优先级；竖屏新增规则集中、限域。若要调整 JSX，只加入布局标识或基于现有组件的语义重排；横屏样式应作截图回归。
- 以内容可用宽度决定单列/多列；沉浸页面可使用 `100dvh`，但题目、字幕、控件必须在同一屏或可滚动容器内到达。
- 重要业务内容和风险提示始终保留可见；摄像头预览、实时情绪、辅助说明可折叠，不能盖住问答。
- 视频、数字人、游戏 iframe 均保持原始比例或安全裁切边界。视频全屏由用户手势触发。
- 设备的 Windows 旋转、浏览器 kiosk、缩放和红外触摸坐标校准属于部署配置；网页适配浏览器最终报告的 CSS 视口。

## 触发与布局规则

- 竖屏优先由 `orientation: portrait` 激活；页面断点再根据可用宽度和高度微调。横屏视口始终使用原布局。
- 1080 × 1920 是主要设计验收视口，另测 900 × 1600、768 × 1024 和 390 × 844 CSS px，以覆盖系统缩放和小屏。
- 核心流程页采用「标题/状态 → 主内容 → 主操作」顺序。长报告使用文档流纵向滚动；问诊与答题采用上方进度、中间题目/数字人、下方操作的分区，并给字幕留安全区。
- 样式实现不得通过全局 `transform: scale` 规避布局问题。触摸目标必须有可见焦点、按下及禁用状态。

## 已知风险

1. 当前数字人问诊和量表大量使用绝对定位与 `overflow-hidden`，需要专门的竖屏结构，不是简单改宽度。
2. 视频页影院面板使用 `vw`/`vh` 绝对坐标；需转换为纵向的播放区与节目列表。
3. 内嵌游戏的 UI 属于 iframe 内容，父页可保证可见区域和滚动，游戏内部触摸细节仍需实机检查。
4. 真实数据截图包含健康信息，仅存本机审查目录，不纳入仓库或公开构建产物。
