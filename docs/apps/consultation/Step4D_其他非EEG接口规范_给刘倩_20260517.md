# Step 4D 其他非 EEG 接口规范（给刘倩）

## 1. 文档目的

这份文档只解决 `Step 4D` 中由刘倩负责的接口与输出规范，覆盖：

- `4D-1` 语音情绪识别落库
- `4D-2` 文本情绪识别落库
- `4D-3` face 连续采样与细粒度结果保存
- `4D-4` pose 连续采样与细粒度结果保存
- `4D-5` turn 级 face / pose 汇总
- `4D-6` session 级 face / pose 汇总

目标不是讨论模型内部怎么实现，而是先把主系统在 `4D` 阶段需要消费的接口、字段和时序定死。

## 2. 当前分工口径

- 主线负责人（肖惠谦）：问诊页前端、`gateway-service` 转发、`consultation-service` 主链推进、右侧看板接线、主库回写
- 朱睿：原始音频上传、MinIO 落地、Dolphin ASR、`audio_uri + transcript_text`
- 刘倩：语音情绪、文本情绪、face、pose、对应聚合输出
- 金伟：EEG 模态与脑电帽硬件

要特别说明：

- 语音情绪和文本情绪虽然依赖朱睿的 `audio-turns` 结果，但 owner 是刘倩
- face / pose 是刘倩主责
- `multimodal-service` 对外仍然是一个服务，不按负责人拆多个服务
- 主系统只认统一接口，不认内部是谁实现

## 3. Step 4D 需要达成的主结果

主系统推进 `Step 4D` 时，最终至少要拿到这 4 类结果：

1. `speech_emotion`
   - 基于整段回答音频的语音情绪结果
2. `text_emotion`
   - 基于最终 `transcript_text` 的文本情绪结果
3. `face_summary`
   - 当前回答窗口内的表情主标签、top 3、质量统计
4. `pose_summary`
   - 当前回答窗口内的姿态主标签、top 3、质量统计

并且这些结果需要同时支持两个消费场景：

- 前端右侧实时看板：读 `/live`
- 回答窗口结束后 turn 级固化：读 `/turns/{turn_id}/bundle`

## 4. 设计结论

### 4.1 不新增单独的“语音情绪提交接口”

V1 不建议让浏览器再额外调用：

- `/speech-emotion`
- `/text-emotion`

因为：

- 语音情绪依赖整段音频
- 文本情绪依赖最终 transcript
- 这两者更适合挂在 `audio-turns` 处理完成后的内部链路上

因此结论是：

- 浏览器仍只上传原始音频到 `audio-turns`
- 刘倩负责在 `multimodal-service` 内部补齐：
  - `speech_emotion`
  - `text_emotion`
- 主系统再统一通过 `/live` 和 `/bundle` 取结果

### 4.2 face / pose 保持独立写接口

face / pose 需要持续采样，所以继续保持：

- `POST /api/v1/multimodal/sessions/{session_id}/captures/face`
- `POST /api/v1/multimodal/sessions/{session_id}/captures/pose`

### 4.3 实时看板只读 `/live`

前端看板不直接读取：

- `audio-turns`
- `captures/face`
- `captures/pose`

前端统一读取：

- `GET /api/v1/multimodal/sessions/{session_id}/live`

### 4.4 turn 结束后只读 `/bundle`

某一道题结束后，下游服务和主链只读取：

- `GET /api/v1/multimodal/sessions/{session_id}/turns/{turn_id}/bundle`

不直接去拼 face 时间流、pose 时间流、语音情绪、文本情绪各自的明细表。

## 5. 刘倩负责的接口与输出

| 接口 / 输出 | 方法 | 负责人 | 用途 | 是否必须 |
| --- | --- | --- | --- | --- |
| `/api/v1/multimodal/sessions/{session_id}/captures/face` | `POST` | 刘倩 | 提交 face 采样帧并保存细粒度结果 | 必须 |
| `/api/v1/multimodal/sessions/{session_id}/captures/pose` | `POST` | 刘倩 | 提交 pose 采样帧并保存细粒度结果 | 必须 |

## 6. 接口 1：face 连续采样写接口

### 6.1 请求

`POST /api/v1/multimodal/sessions/{session_id}/captures/face`

`Content-Type: multipart/form-data`

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `consultation_session_id` | `string` | 是 | 主问诊会话 id |
| `turn_id` | `string` | 否 | 如果当前题已有 turn id，直接传入 |
| `question_key` | `string` | 是 | 当前题 key |
| `capture_started_at` | `string` | 是 | 当前 face 采样时间点或片段开始时间 |
| `capture_ended_at` | `string` | 是 | 当前 face 采样时间点或片段结束时间 |
| `frame_index` | `integer` | 是 | 本轮采样序号 |
| `mime_type` | `string` | 是 | 例如 `image/jpeg` |
| `image_file` | `binary` | 是 | 当前 face 抽样图像 |

### 6.2 行为要求

刘倩这边必须完成：

1. 接收当前帧或短片段
2. 执行表情识别
3. 保存细粒度时间流结果
4. 返回本次 face 识别结果

### 6.3 返回要求

```json
{
  "capture_id": "face-cap-001",
  "session_id": "mm-session-id",
  "question_key": "chief-complaint-001",
  "modality": "face",
  "processing_status": "completed",
  "primary_label": "平静",
  "primary_score": 0.76,
  "top_3_labels": [
    { "label": "平静", "score": 0.76 },
    { "label": "专注", "score": 0.14 },
    { "label": "轻度低落", "score": 0.06 }
  ],
  "quality_flags": {
    "no_face": false,
    "blur": false,
    "low_light": false
  },
  "capture_started_at": "2026-05-17T10:01:11Z",
  "capture_ended_at": "2026-05-17T10:01:11Z",
  "created_at": "2026-05-17T10:01:11Z"
}
```

## 11. 落库时机要求

### 11.1 face / pose

每次采样上行时：

- 写细粒度 `multimodal_capture`
- 写本次推理结果

每个回答窗口结束时：

- 生成当前题的 `face_summary`
- 生成当前题的 `pose_summary`

整个问诊会话结束时：

- 生成 session 级 `face_summary`
- 生成 session 级 `pose_summary`

### 11.2 speech / text

当 `audio-turns` 已经拿到：

- `audio_uri`
- `transcript_text`

时，刘倩侧开始补齐：

- `speech_emotion`
- `text_emotion`

当两者处理完成后：

- 更新 `/live`
- 更新 turn 级 `/bundle`

## 12. 前端看板约束

为了让右侧看板稳定，刘倩负责的模态输出必须遵守：

1. 字段名固定，不能今天 `label` 明天 `emotion`
2. 所有模态都要带 `status`
3. 没结果时也返回稳定空结构
4. `top_3_labels` 结构统一
5. `updated_at` 必须可用于前端判断“是不是最新结果”

## 13. 非目标

这份规范当前不要求刘倩这边负责：

- 原始音频落 MinIO
- Dolphin ASR
- EEG
- 问诊状态机推进
- 主系统 turn 表更新
- 最终风险结论

## 14. 验收口径

刘倩这边接口准备完成，视为满足：

1. `captures/face` 可以持续收 face 帧并返回结果
2. `captures/pose` 可以持续收 pose 帧并返回结果
3. `audio-turns` 对应的语音情绪和文本情绪能补齐
4. `/live` 能稳定给前端看板返回 `speech/face/pose/text`
5. `/turns/{turn_id}/bundle` 能稳定给主链返回 turn 级汇总
6. turn 级 `face_features` / `pose_features` / `speech_features` / `text_features` 字段稳定
