# `consultation` 应用设计概览

## 2026-10-22 当前代码状态

当前应用已经使用 React / TypeScript，并具备问诊、量表及后续页面。EEG 情绪镜像代码已加入现有看板；详见 [融合实施记录](../../multiEmo/eeg-mirror-implementation_20261022.md)。下文早期占位描述保留为历史阶段记录。

## 1. 概述

`consultation` 是面向患者/受试者的主交互应用，负责承接 MCS 从“患者登录”到“数字人交互问诊、量表问诊、结果展示、干预执行、回顾与再评估”的前台体验。

在当前阶段，它是整个产品主链的主入口，不是一个普通信息展示页。

## 2. 核心设计结论

- 患者侧只有一条主链，不再分裂出单独的数字医生选择页。
- 前端只负责交互与状态呈现，不承载问诊状态机、量表计分和风险计算。
- 当前静态壳只用于过渡，正式实现应尽快切到 React + TypeScript + TSX。
- 页面风格应学习旧 `Depression` 的视觉语言，但实现方式要保持前后端分离。

## 3. 职责边界

负责：

- 患者注册、登录、退出
- 问诊准备信息填写与确认
- 正式问诊入口状态展示
- 后续数字人问诊界面
- 后续量表作答界面
- 后续临床决策结果页、干预页、回顾页

不负责：

- 用户认证规则本身
- 会话 token 生成与校验
- 问诊状态机执行
- 量表计分和聚合计算
- 风险计算和干预推荐算法

这些逻辑都属于 `gateway-service` 或各后端领域服务。

## 4. 上下游依赖

上游输入：

- 浏览器中的会话 Cookie
- `gateway-service` 提供的启动摘要数据
- `identity-service` 保存的问诊准备字段
- 后续 `consultation-service`、`assessment-service`、`risk-service` 的业务数据

下游输出：

- 问诊准备表单提交
- 后续问诊轮次输入
- 后续量表答案提交
- 后续干预反馈与再评估确认

## 5. 当前实现状态

已完成：

- 静态前端壳
- 登录/注册
- 问诊准备表单
- 正式问诊入口页
- 基于 gateway 的 consultation 会话创建 / 启动 / 轮次提交
- 规则版数字人问诊浏览器链路

未完成：

- 基于 React + TypeScript + Vite 的正式前端骨架
- 量表问答 UI
- 结果页和干预页

已知限制：

- 当前仍是原生 HTML + JS 占位实现
- 视觉风格尚未对齐旧 `Depression` 系统
- 问诊界面当前仍以文字输入模拟语音结果

## 6. 目标技术方向

后续应切换到与 `aic-coralreef` 一致的应用结构：

- `client/`: React + TypeScript + Vite + TSX
- `server/`: 轻量静态资源托管层

视觉风格则应向旧 `Depression` 系统靠拢：

- 蓝色主色系
- 大圆角白底卡片
- 左导航/顶栏式工作区
- 中文信息密度与医疗咨询氛围

## 7. 非目标

- 不把业务主逻辑写回应用侧轻量服务层
- 不引入旧 Flask 模板直渲染
- 不在患者侧提供数字医生样式选择页
