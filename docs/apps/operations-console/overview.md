# `operations-console` 应用设计概览

## 1. 概述

`operations-console` 是面向管理员和研究人员的后台应用，用于管理 MCS 的用户、流程资源、配置项、记录查询与导出。

它不是面向患者的业务入口，而是用于支撑整条主链稳定运行的运维与研究工作台。

## 2. 核心设计结论

- `operations-console` 不是通用后台模板，而是围绕 MCS 主流程定制的研究与运维控制台。
- 后台所有数据访问仍统一经过 `gateway-service`，不让浏览器直接打各领域服务。
- 前期先做“只读概览 + 只读资源检查 + 记录检索”，再逐步开放受控配置能力。
- 后台对流程资源的修改不能直接让浏览器写文件系统，必须通过受控接口、校验和审计链路完成。

## 3. 职责边界

负责：

- 管理员/研究人员登录后的后台访问入口
- 当前系统工作流概览展示
- 数字医生人设目录、剧本、量表、风险规则、干预方案的后台查看
- 后续用户与权限管理
- 后续问诊记录、量表记录、风险结果、干预记录的检索与导出
- 后续再评估任务的查看与管理

不负责：

- 患者问诊交互
- 数字人问诊状态机执行
- 量表逐题作答
- 临床风险计算本身
- 干预执行内容本身

这些能力属于各领域服务，后台只负责管理与观察。

## 4. 上下游依赖

上游输入：

- 浏览器中的会话 Cookie
- `gateway-service` 提供的后台聚合接口
- `identity-service` 提供的用户与角色信息
- 后续 `consultation-service`、`assessment-service`、`risk-service`、`intervention-service`、`followup-service` 的后台接口

下游输出：

- 用户和权限操作请求
- 流程资源查看与发布请求
- 记录查询和导出请求
- 再评估管理请求

## 5. 当前实现状态

已完成：

- 静态后台壳
- 管理员/研究员登录
- 基础 workflow 概览
- 数字医生配置目录概览

未完成：

- 正式 React + TypeScript + TSX 后台骨架
- 用户与权限管理页
- 流程资源查看页
- 量表、风险、干预配置页
- 记录检索、导出与再评估管理页

已知限制：

- 当前只是最小后台壳，不适合作为正式控制台继续叠加复杂能力
- 还没有后台专用接口，只复用了前台链路中的 `users/me` 和 `bootstrap`
- 没有配置校验、审计记录和发布流程

## 6. 目标技术方向

后续应切换到与 `aic-coralreef` 一致的应用结构：

- `client/`: React + TypeScript + Vite + TSX
- `server/`: 轻量静态资源托管层

后台风格应与患者端保持系统一致性，但在信息密度和布局上更偏管理台：

- 左侧导航 + 顶部操作区
- 更高的信息密度
- 更清晰的列表、筛选、状态标签和时间线
- 更强调操作审计与变更可追踪

## 7. 非目标

- 不让后台前端直接写 `packages/workflow-resources/` 文件
- 不绕开 `gateway-service` 直接访问各后端服务
- 不把研究分析脚本散落进前端工程
