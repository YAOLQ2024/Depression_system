# `operations-console` 应用实施任务

## 当前 owner 与协作边界

- 当前 owner：主线负责人（仓库维护者）
- 模块职责：负责研究与运维控制台的页面、导航、查询、配置审阅与导出入口
- 不在本模块内解决：具体资源规则计算、报告生成、量表计分、风险判断，这些逻辑留在领域服务

## 当前交付目标

- 把当前后台占位页收敛为正式后台前端工程
- 先保证只读查询与流程观察能力，再逐步开放受控编辑
- 为后续多人联调提供统一后台入口

## 可直接认领的任务包

### P0：后台工程化收口

- APP-OPS-01：把当前静态后台迁移到 `React + TypeScript + Vite + TSX`
- APP-OPS-02：建立后台路由、导航、权限入口和基础布局
- APP-OPS-03：统一后台设计变量、表格、筛选面板、状态标签组件

### P1：只读查询阶段

- APP-OPS-11：实现后台登录页、无权限页和概览页正式版本
- APP-OPS-12：实现用户、角色、workflow、剧本、量表、风险规则、干预目录只读详情
- APP-OPS-13：实现问诊记录、量表记录、风险记录、干预记录查询页
- APP-OPS-14：实现导出任务入口与结果查看占位

### P2：受控编辑与审计阶段

- APP-OPS-21：实现受控配置编辑页与发布确认流程
- APP-OPS-22：实现资源校验、差异比对、审计记录查看
- APP-OPS-23：实现再评估任务管理与研究统计视图

## 依赖与协作约束

- 依赖 `gateway-service` 提供后台聚合接口
- 依赖 `identity-service` 提供后台角色与用户管理能力
- 依赖各领域服务提供稳定的只读查询接口和资源详情接口
- 未形成审计与回滚方案前，不直接在后台开放“修改线上资源文件”的能力

## 验收口径

- 后台能统一查看主链记录和资源配置，不需要直接进入数据库或登录多个服务
- 查询页字段、筛选项、状态名与各服务文档保持一致
- 后台页面与患者端一样，所有 API 请求统一走 `gateway-service`
