# Jetson 局域网修复与验收（2026-10-07）

本次范围：旧日志清理、局域网 HTTPS 与证书信任、登录与媒体上传采集链路、此前确认的两处前端错误。

## 已完成的修改

- 清空 `/var/log/uvcdynctrl-udev.log`，原大小 `6,951,829,570` 字节，释放约 6.5 GiB。保留日志最后 64 KiB 和原文件元数据供追溯。
- 将 `/usr/lib/udev/uvcdynctrl` 的 `debug=1` 改为 `debug=0`，保留 UVC 动态控制加载，停止该工具输出调试日志。后续升级 `uvcdynctrl` 软件包时应检查这一设置是否被覆盖。
- Jetson 上的前端容器取消直接发布 HTTP 3000/3001，由 Caddy 接管并以 308 分别跳转到 HTTPS 443/8443，保留访问路径和查询参数。基础开发 Compose 配置保留。
- 增加 `/local-ca.crt` 公开根证书下载入口，仅映射到 `jetson-local-ca.pem`，不提供目录浏览或私钥下载。
- 在本机 `/usr/local/share/ca-certificates/` 安装公开 CA，并通过系统 `update-ca-certificates` 脚本更新信任库；在当前用户 Chromium NSS 数据库中导入 CA 的 SSL 信任。
- 修复风险筛查视频 URI 为 `null` 时调用 `split` 的错误，保留视频版本参数和播放片段规则。
- 结果页复用非空的分数说明变量，消除 `InfoTooltip` 的 TypeScript 空值类型错误。
- 重新构建并部署问诊前端，重建管理前端与 Caddy 容器应用端口配置；验收脚本的前端 readiness 改为检查 HTTPS 入口。

旧日志尾部、工具原文件、原系统 CA bundle 和原 NSS 数据库备份位于本机 `.codex-tmp/lan-fix/`。该目录权限为 0700，已排除 Git，不包含服务器证书私钥备份。

## 客户端剩余步骤

每台局域网设备首次访问需要安装并信任公开 CA，然后在浏览器和系统隐私设置中允许摄像头、麦克风。服务器无法替用户修改其他设备的信任库或授权。访问地址和各平台步骤见 [局域网客户端访问说明](lan-client-access.md)。

本轮未操作其他设备或路由器。当前证书覆盖的 LAN IP 为 `192.168.50.41`；如果地址变化，需要签发覆盖新地址的服务器证书。实际手机/电脑完成准备页授权和录制上传后，才能确认对应设备的硬件与浏览器兼容性。

磁盘分区、Ollama/模型资源、内存配置及其他优化均未调整。改动保留在工作区，未提交或推送。
