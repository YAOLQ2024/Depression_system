# `assessment-service` 服务流程设计

## 1. 量表会话启动

1. 接收来自 `consultation-service` 的移交数据
2. 读取量表策略与活跃量表目录
3. 创建 `assessment_session`
4. 返回第一份量表和第一题

## 2. 量表规则与选择

当前策略：

- 先以 4 个活跃量表为主
- 必做量表和可选量表都从资源配置读出
- 当前版本不启用 `SCL-90`

## 3. 逐题作答流程

1. 返回当前题目
2. 接收患者语音答案
3. 归一化到量表选项
4. 保存答案
5. 更新当前量表进度
6. 判断当前量表是否完成

## 4. 单量表完成流程

1. 计算单量表得分
2. 立即后端落库
3. 不立即在前端显示结果
4. 切换到下一量表

## 5. 全量表完成流程

1. 汇总全部量表结果
2. 组合多模态辅助特征
3. 生成 `assessment_aggregate_payload`
4. 移交给 `risk-service`

## 6. 异常分支

- 当前量表定义缺失
- 患者答案无法归一化
- 重复提交同一题
- 会话状态与当前题号不一致

## 7. 实现约束

- 量表定义必须从 yaml 读，不写死在代码里
- 每个量表完成要可审计、可回放
- 当前版本不让单量表结果提前在前端暴露
