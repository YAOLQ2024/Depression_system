# `assessment-service` 服务实施任务

## 当前 owner 与协作边界

- 当前 owner：主线负责人（仓库维护者）
- 模块职责：负责 4 个活跃量表的会话、作答、计分、聚合输出
- 当前范围：`PHQ-9`、`SDS`、`SAS`、社会功能缺陷量表
- 暂不纳入：`SCL-90`

## 当前交付目标

- 把量表阶段补成主链上的正式后端服务
- 固定量表会话、单题提交、量表完成、全量聚合输出结构
- 为后续 `risk-service` 提供稳定的量表聚合输入

## 可直接认领的任务包

### P0：量表骨架与资源

- ASSESS-01：实现 4 个活跃量表的资源装载器
- ASSESS-02：设计量表会话、答案、结果表结构
- ASSESS-03：设计题目索引、反向计分与分值归一化方式

### P1：主链接口

- ASSESS-11：实现创建量表会话接口
- ASSESS-12：实现逐题作答接口
- ASSESS-13：实现单量表完成落库
- ASSESS-14：实现全量表完成聚合输出，并回传 `risk-service` 可消费 payload

### P2：恢复、导出与关联字段

- ASSESS-21：接入多模态关联字段
- ASSESS-22：增加量表进度恢复与断点续答
- ASSESS-23：增加后台查看和导出支持

## 依赖与协作约束

- 依赖量表 YAML 定义质量
- 依赖 `consultation-service` 产出稳定的移交数据
- 依赖患者端前端补齐量表作答 UI
- 不要为了赶进度把 `SCL-90` 提前拉回主链

## 验收口径

- 4 个活跃量表都能独立完成作答与计分
- 聚合输出字段命名、分值和结论口径稳定
- 量表阶段结束后，`risk-service` 不需要做二次清洗就能直接消费
