# `assessment-service` 服务设计概览

## 1. 概述

`assessment-service` 负责 MCS 的量表问诊阶段，是“数字人问诊”之后的第二段核心采集链。

当前活跃主链只做 4 个量表：

- `PHQ-9`
- `SDS`
- `SAS`
- `社会功能缺陷量表`

`SCL-90` 只保留资源占位，不纳入当前 V1 主链。

## 2. 核心设计结论

- `assessment-service` 是量表问诊阶段的专属服务，不和数字人问诊服务混写。
- 当前先稳定 4 个活跃量表，`SCL-90` 只保留占位，不进入主链。
- 量表定义必须配置化，不能把题目和计分规则散落在代码里。
- 每个量表完成后立即落库，但前端不提前展示单量表结果。

## 3. 职责边界

负责：

- 读取量表定义
- 创建量表会话
- 按规则调度必做/可选量表
- 接收逐题作答
- 单量表完成即落库
- 全量表完成后输出聚合结果

不负责：

- 患者认证
- 数字人问诊状态机
- 临床风险最终分层
- 干预方案选择

## 4. 上下游

上游：

- `gateway-service`
- `consultation-service`
- `consultation` app

下游：

- `packages/workflow-resources/scales/*.yaml`
- 后续数据库
- 后续 `multimodal-service`

## 5. 当前实现状态

已实现：

- 健康检查
- 4 个活跃量表资源装载器
- 量表会话、答案、结果数据模型
- 量表目录读取
- 量表会话创建
- 量表会话状态读取
- 当前题目答案提交与单量表计分
- 全量表完成后的聚合结果生成

待实现：

- `gateway-service` 与患者端前端正式接入
- 更完整的逐题恢复、断点续答和后台查询支持
- 与 `risk-service` 的正式移交链路

## 6. 非目标

- 当前阶段不恢复 `SCL-90`
- 不在服务里写死量表定义
