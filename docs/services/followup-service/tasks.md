# `followup-service` 服务实施任务

## 当前 owner 与协作边界

- 当前 owner：朱睿
- 配合方：主线负责人负责患者端与后台接入，`risk-service`、`intervention-service` 为上游输入
- 模块职责：负责回顾记录、时间线事件、再评估任务、报告导出
- 不在本模块内解决：风险分层、干预计划推荐、身份鉴权

## 当前交付目标

- 把回顾与再评估阶段从前端占位页收成独立服务
- 固定事件类型、时间线结构、再评估任务结构和导出入口结构
- 为闭环展示和研究导出提供统一输出

## 可直接认领的任务包

### P0：数据模型与事件标准

- FOLLOWUP-01：设计回顾记录、时间线事件、再评估任务、导出报告数据模型
- FOLLOWUP-02：固定上游输入结构和下游输出结构
- FOLLOWUP-03：设计统一事件类型枚举

### P1：主链接口与导出占位

- FOLLOWUP-11：实现回顾记录生成接口
- FOLLOWUP-12：实现时间线查询接口
- FOLLOWUP-13：实现再评估任务创建与更新接口
- FOLLOWUP-14：实现导出报告占位链路

### P2：正式报告与闭环策略

- FOLLOWUP-21：接入正式报告模板
- FOLLOWUP-22：增加异步导出、下载授权和审计记录
- FOLLOWUP-23：增加再评估提醒和闭环完成策略

## 依赖与协作约束

- 依赖 `risk-service`、`intervention-service` 输出结构稳定
- 风险、干预和回顾字段命名必须统一
- 导出模板和通知机制需要先有明确方案，再开放前端入口

## 验收口径

- 同一用户的一次完整流程能在时间线上按统一事件名串起来
- 再评估任务有独立建模，不是页面提示文案
- 导出链路即使先是占位版本，也要有明确任务状态与文件元数据结构
