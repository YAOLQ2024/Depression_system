# `followup-service` 服务流程设计

## 1. 回顾记录生成

1. 接收来自上游各阶段的结构化结果
2. 生成一次完整回顾记录
3. 提炼摘要供患者侧和后台查看

## 2. 时间线沉淀

1. 把问诊、量表、风险、干预等关键事件写入统一时间线
2. 标记来源服务、来源记录和发生时间
3. 形成可按时间回放的事件序列

## 3. 再评估任务创建

1. 根据风险结果、干预反馈或后台规则决定是否需要再评估
2. 创建再评估任务
3. 生成下一轮筛查入口信息

## 4. 报告导出流程

1. 接收导出请求
2. 汇总结构化记录
3. 生成导出报告
4. 返回下载信息或异步任务状态

## 5. 异常分支

- 上游记录缺失
- 时间线事件重复写入
- 再评估任务冲突
- 报告生成失败

## 6. 实现约束

- 时间线事件模型必须统一
- 回顾记录不能只靠拼接字符串生成
- 再评估任务需要有清晰状态机，不能只是“有或没有”
