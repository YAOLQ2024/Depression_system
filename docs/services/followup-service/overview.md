# `followup-service` 服务设计概览

## 1. 概述

`followup-service` 负责 MCS 中“对话回顾与再评估”阶段的记录沉淀、时间线整理、再评估任务生成和报告导出。

它是整个系统形成闭环的关键服务。

## 2. 核心设计结论

- `followup-service` 不是简单的历史记录库，而是负责把整条主链沉淀成可追踪事件序列。
- 它的输入来自问诊、量表、风险、干预多个阶段，所以数据模型必须围绕“时间线”和“再评估任务”组织。
- 再评估不能只是一个日期字段，而应是可管理、可触发、可关闭的任务对象。
- 导出报告应基于结构化记录生成，而不是从前端页面拼接。

## 3. 职责边界

负责：

- 对话回顾记录生成
- 事件化时间线沉淀
- 再评估任务创建与管理
- 历史查看与报告导出
- 下一轮筛查入口信息生成

不负责：

- 问诊状态机执行
- 量表作答与计分
- 风险判断
- 干预计划生成

## 4. 上下游

上游：

- `consultation-service`
- `assessment-service`
- `risk-service`
- `intervention-service`

下游：

- `operations-console`
- `consultation` 应用
- 后续导出与通知链路

## 5. 当前实现状态

已实现：

- 只有健康检查占位

待实现：

- 回顾记录模型
- 时间线模型
- 再评估任务模型
- 导出报告链路

已知限制：

- 当前没有统一事件模型
- 没有报告模板和导出策略
- 没有再评估触发策略和提醒机制

## 6. 非目标

- 不在本服务内重复保存所有原始大对象
- 不替代各领域服务自己的业务主表
- 不把前端页面展示逻辑写进本服务
