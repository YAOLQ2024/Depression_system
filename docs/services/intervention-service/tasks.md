# `intervention-service` 服务实施任务

## 当前 owner 与协作边界

- 当前 owner：朱睿
- 配合方：主线负责人负责主链集成，`risk-service` 输出由朱睿本人同步维护
- 模块职责：负责干预目录、干预计划生成、执行会话、执行事件、用户反馈
- 不在本模块内解决：风险分层计算、再评估任务创建、患者端页面实现

## 当前交付目标

- 把调控执行阶段从规则结果中拆成独立服务
- 固定干预计划输出和反馈输入格式
- 为后续真实视频、音频、图文资源接入留出标准化接口

## 可直接认领的任务包

### P0：目录与数据模型

- INTERVENTION-01：细化干预目录结构
- INTERVENTION-02：设计干预计划、执行会话、反馈数据模型
- INTERVENTION-03：固定计划输出与反馈输入格式

### P1：计划生成与执行链路

- INTERVENTION-11：实现干预计划生成接口
- INTERVENTION-12：实现执行会话创建与状态查询
- INTERVENTION-13：实现执行事件记录和用户反馈接口
- INTERVENTION-14：整理干预资源元数据，保证前端能直接渲染

### P2：真实资源与策略增强

- INTERVENTION-21：接入真实音频、视频、图文资源
- INTERVENTION-22：增加计划推荐优化和后台审查能力
- INTERVENTION-23：增加与再评估任务的联动策略

## 依赖与协作约束

- 依赖 `risk-service` 输出稳定的风险结果和干预入口数据
- 干预目录配置必须补全适用条件、禁忌条件、资源信息
- 所有数字人视频资源的命名、版本、适用场景需要同步写入目录元数据

## 验收口径

- 给定同一风险入口数据，可以稳定生成可解释的干预计划
- 执行过程能完整记录开始、暂停、完成、反馈等关键事件
- 患者端和后台都能只根据服务输出字段完成渲染，不需要额外猜测资源含义
