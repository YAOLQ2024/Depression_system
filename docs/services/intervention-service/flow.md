# `intervention-service` 服务流程设计

## 1. 干预计划生成

1. 接收风险结果和干预入口数据
2. 读取干预目录
3. 匹配适用的干预方式
4. 生成个性化干预计划

## 2. 执行会话启动

1. 创建干预执行会话
2. 返回当前计划内容与执行方式
3. 前端开始执行对应内容

## 3. 执行过程记录

1. 记录开始、暂停、继续、完成、跳过等事件
2. 保存执行时长和中断原因
3. 更新当前执行状态

## 4. 用户反馈回写

1. 接收用户反馈评分和文本
2. 标记本次执行效果
3. 提炼对后续再评估有帮助的提示信息

## 5. 与主流程的关系

- 干预计划来源于 `risk-service`
- 执行记录与反馈流向 `followup-service`
- 必要时可触发“需要尽快再评估”的提示

## 6. 异常分支

- 没有可匹配方案
- 执行资源不可用
- 执行中断
- 用户跳过反馈

## 7. 实现约束

- 干预目录配置必须可扩展
- 不能只记录“做过/没做过”，要记录执行过程
- 反馈数据必须兼容后续回顾和再评估链路
