# `consultation-service` 服务流程设计

## 1. 问诊会话启动

1. gateway 传入当前用户与问诊准备上下文
2. 服务创建 `consultation_session`
3. 绑定 `consultation-v1` workflow
4. 绑定默认数字医生配置
5. 把 `current_node_id` 初始化为 `stage-01` 的入口节点

## 2. 四个固定子模块流转

### 2.1 初始问候与流程说明

- 读取患者基础档案
- 读取系统绑定的数字人配置
- 检查语音输入和同意状态
- 进入正式问诊

### 2.2 主诉采集

- 提问
- 接收语音或兜底输入
- 转写
- 抽取主诉关键词和摘要

### 2.3 症状筛查规则式问诊

- 根据主诉关键词选路径
- 逐轮问答
- 每轮保存原始输入、转写文本和结构化字段
- 形成症状筛查结构化结果

### 2.4 高风险问题排查

- 独立执行安全门逻辑
- 如果无高风险，生成量表移交数据
- 如果高风险，暂停标准流程

## 3. 三类分支处理

正常回答：

- 正常推进到下一节点

沉默无反馈：

- 先重试
- 再提供按钮/文字输入兜底

识别失败或答非所问：

- 重述问题
- 允许短答案或手动输入
- 必要时将字段标记为“暂未明确”

## 4. 会话状态建议

- `draft`
- `running`
- `waiting_user_input`
- `paused_for_retry`
- `paused_for_human_review`
- `handoff_ready`
- `completed`

## 5. 异常分支

- workflow 资源缺失
- 节点配置非法
- ASR 不可用
- 高风险强制中断

## 6. 实现约束

- 规则引擎必须可配置，不把剧本写死在 Python if/else 里
- 高风险排查必须与一般症状筛查追问分开建模
