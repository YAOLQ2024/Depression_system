# `identity-service` 服务流程设计

## 1. 注册流程

1. 接收邮箱、密码、姓名
2. 检查邮箱是否已存在
3. 生成盐值和密码哈希
4. 写入用户表
5. 返回公开用户结构

## 2. 登录流程

1. 根据邮箱查用户
2. 校验密码哈希
3. 创建 session token
4. 写入 sessions 表
5. 返回 `session_token + user`

## 3. 当前用户查询流程

1. 读取 `Authorization` 头
2. 解析 Bearer token
3. 根据 token 查 sessions 表
4. 检查是否过期
5. 联表返回用户公开信息

## 4. 问诊准备更新流程

1. 校验当前登录用户
2. 从请求体中过滤允许字段
3. 更新用户记录
4. 根据是否存在有效输入更新 `profile_status`
5. 返回更新后的公开用户结构

## 5. 异常分支

邮箱重复：

- 返回 4090

密码错误：

- 返回 4010

缺 token：

- 返回 4011

session 无效或过期：

- 返回 4012

## 6. 后续约束

- 身份域保持小而稳
- 问诊准备字段可以继续放这里过渡，但正式业务记录不要继续往这里加
