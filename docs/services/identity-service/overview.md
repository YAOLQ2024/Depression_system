# `identity-service` 服务设计概览

## 1. 概述

`identity-service` 是 MCS 当前最先落地的真实后端服务，负责身份、角色、会话以及问诊准备基础字段。

它是主链入口依赖，但不是业务流程编排服务。

## 2. 核心设计结论

- `identity-service` 只负责身份、角色、会话和问诊准备基础字段，不继续吞业务域数据。
- 当前已切到 PostgreSQL，并通过 Alembic 管理表结构迁移。
- 问诊准备字段暂时放在身份域里可以接受，但正式问诊记录和量表结果必须留在各自领域服务。

## 3. 职责边界

负责：

- 用户注册
- 用户登录
- 会话 token 创建与校验
- 角色定义
- 用户基础资料与问诊准备字段保存

不负责：

- workflow 资源读取
- 数字人问诊状态机
- 量表会话和计分
- 风险计算

## 4. 上下游

上游：

- `gateway-service`

下游：

- PostgreSQL
- Alembic migration 链路

## 5. 当前实现状态

已实现：

- 注册/登录/退出
- 示例账号 seed
- 会话 token 存储
- `users/me`
- `users/me/profile`
- PostgreSQL 存储
- Alembic 启动迁移

待实现：

- 更完整的用户档案模型
- 角色权限更细分的校验
- 审计字段与后台查询能力

已知限制：

- session token 只存在数据库，没有更丰富的审计字段

## 6. 非目标

- 不在这里实现问诊记录和量表结果
- 不在这里实现复杂 RBAC 控制台逻辑
