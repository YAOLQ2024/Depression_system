# `identity-service` 服务实施任务

## 当前 owner 与协作边界

- 当前 owner：主线负责人（仓库维护者）
- 模块职责：负责用户、会话、角色、问诊准备基础资料与后台权限入口
- 不在本模块内解决：正式问诊内容、量表答案、风险结论、干预数据

## 当前交付目标

- 保持当前登录/注册/资料更新接口稳定
- 维持 `PostgreSQL + Alembic + SQLAlchemy` 基线，禁止退回 SQLite 或手写拼接 SQL
- 为后台用户与权限管理预留扩展空间

## 可直接认领的任务包

### P0：基础稳定性

- ID-01：固定当前接口行为、错误码和 Cookie 生命周期
- ID-02：把示例账号 seed、session TTL、CORS 配置收成清晰可控的配置项
- ID-03：维持 migration 驱动建表，不在应用启动阶段隐式建表

### P1：用户与会话模型扩展

- ID-11：为用户档案和问诊准备字段设计更清晰的数据表结构
- ID-12：增加审计字段、账号状态和更明确的 session 生命周期管理
- ID-13：补充后台只读查询所需的筛选字段

### P2：后台管理能力

- ID-21：实现用户查询、筛选、禁用能力
- ID-22：实现密码重置、账号状态流转、更多组织字段
- ID-23：补充审计日志与后台权限矩阵

## 依赖与协作约束

- 所有数据库变更先写 Alembic migration，再上服务代码
- 新增字段必须先确认是否属于身份域，避免把业务数据堆回本服务
- 后台权限模型变更要提前同步 `operations-console` 和 `gateway-service`

## 验收口径

- 用户与会话数据只存在身份域，不掺杂问诊业务明细
- 运行期数据库操作全部使用 SQLAlchemy/参数化访问，不出现拼接 SQL
- 会话与权限相关变更能通过后台和前台两端联调验证
