一、记录范围与阶段结论

本轮对 MCS 当前工作区和 Jetson 上运行的 Docker 服务进行检查。执行 git fetch --all --prune 后，origin/feature/zhurui 与本地 feature/zhurui 均为提交 03c87c1，没有远端新提交；保留了工作区已有的未提交 UI 改动。14 个容器均处于运行状态；网关、身份、问诊、评估、风险、多模态、干预和随访 8 个服务的 /health/ready 均返回 HTTP 200。PostgreSQL、Redis 和 MinIO 的只读连通检查通过。咨询端与运营端 HTTPS 页面均能打开。

前端 TypeScript 检查、生产构建及 10 项前端单元测试通过；Risk Service 13 项、Consultation Service 23 项、Multimodal Service 32 项、EEG 工具 31 项测试通过，共 99 项 Python 用例通过。scripts/jetson-smoke.py 的端到端烟雾流程也通过：HTTPS/页面/视频、注册登录、资料、问诊创建启动、五模态预热、文本推理和 4 秒合成音频上传、对象存储、CUDA ASR 及情绪分析。使用 Chromium 对诗歌页进行 1080×1920 竖屏和 1024×600 横屏截图检查。随后已按当前工作区重建 consultation 镜像并更新容器；默认 HTTPS 实际返回新构建资源，两首诗歌页引用 portrait-layout-v3，竖屏 Chromium 检查可见页面内容铺满浏览器视口。横屏截图未见明显内容越界。

重建过程中发现 LAN HTTPS Compose 组合把 Caddy 的宿主机 3000/3001 端口与咨询端、运营端开发端口重复映射，导致 consultation 首次重建后启动失败。已在 docker-compose.lan-https.yml 清除这两个应用容器的宿主机端口映射（Caddy 继续拥有 HTTP 重定向端口），Compose 校验通过，consultation 容器已运行，默认 HTTPS 首页和 readiness 均返回 HTTP 200。MCS-UI-001 已复测通过。

后端 pytest 依赖安装在 /tmp/mcs-system-test-deps 独立目录中，没有改动系统 Python 或运行服务容器；Multimodal 测试额外安装了 httpx、Transformers 等导入依赖。端到端烟雾测试在当前数据库中创建了明确标记为非真实患者的合成账号和问诊记录；没有访问或修改真实患者数据。PHQ-9 全量作答到风险/干预/报告链、恢复演练、摄像头/麦克风实际采集及 EEG 真机数据采集没有执行。故本记录覆盖自动化、运行环境和一条多模态烟雾流程，不构成完整临床业务验收。
