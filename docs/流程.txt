1. 患者登录

- 使用账户信息和患者身份信息进入系统。
- 登录成功后加载患者基础档案、既往检查结果、权限激活状态与设备状态。

2. 问诊准备

- 完善或确认基础档案信息。
- 由系统绑定默认数字人问诊配置。
- 检查语音输入、数字人口型/音频资源、交互设备状态。
- 展示问诊说明、交互规则与注意事项，患者确认后进入正式问诊。

3. 数字人交互问诊

数字人交互问诊固定拆成 4 个子模块：

一：初始问候与流程说明子模块

- 加载患者基础档案信息与系统分配的数字人配置。
- 数字人完成开场说明、交互规则说明、问诊目的确认。
- 患者确认开始后，系统进入正式问诊状态。

二：主诉采集子模块

- 数字人提出主诉问题。
- 患者语音回答。
- 系统进行语音识别与文本转写。
- 提取主诉原始文本、主诉关键词和主诉摘要。

三：现病史规则式问诊子模块

- 根据主诉关键词进入对应规则路径。
- 围绕症状持续时间、频率/强度、伴随表现、生活学习工作影响、既往求助情况等进行规则式追问。
- 如需要采集家庭背景、既往病史、家族史、压力源等信息，应作为该子模块中的规则节点，而不是单独再建产品一级阶段。
- 每轮问答都要保存患者原始回答、转写文本、结构化字段和当前问诊状态。

四：高风险问题排查子模块

- 对自伤、自杀意念、自杀计划、近期极端行为、现实支持缺失等高风险信号进行单独排查。
- 若未触发高风险，则保存结果并返回主流程。
- 若触发高风险，则输出高风险提示，暂停标准流程，保留结果并进入人工介入或安全处置分支。

数字人交互问诊阶段固定要求：

- 前期不上 LLM + RAG 主链，先以规则树和状态机驱动。
- 必须处理“正常回答 / 沉默无反馈 / 答非所问或识别失败”三类分支。
- 必须保留问诊结构化记录、主诉摘要、现病史结果和高风险排查结果。

4. 量表问诊

量表问诊固定拆成 2 个子模块：

一：量表规则与选择子模块

- 读取量表配置规则。
- 区分必做量表与可选量表。
- 展示量表说明、作答方式与作答注意事项。
- 患者确认后进入量表作答状态。

二：量表问诊子模块

- 加载当前量表题目。
- 题目展示与语音播报。
- 患者全程语音作答，答完自动进入下一题。
- 自动计分、更新进度、判断当前量表是否完成。
- 完成后保存当前量表结果并进入下一量表或汇总阶段。

当前固定量表包括：

- PHQ-9
- SDS
- SAS
- 社会功能缺陷量表

量表阶段固定要求：

- 每完成一个量表立即后端落库。
- 前端不立即显示单量表结果。
- 等全部必做量表和患者所选量表完成后，再统一计算并展示聚合结果。
- 可同步采集语音、表情、脑电、姿态等多模态信息，作为辅助参考，不作为唯一判定依据。

5. 临床决策

- 输入：问诊结构化结果、量表结果、多模态特征、临床决策规则。
- 输出：风险等级、风险提示、就诊建议、生活建议、后续干预线索。

6. 调节干预

- 根据临床决策结果选择调节方式、调节内容与调节强度。
- 可输出并执行的方式包括：
  - 语音或音频引导
  - 呼吸放松训练
  - 舒缓音乐
  - 视频或动画引导
  - 图文卡片
- 保存干预执行记录和用户反馈。

7. 对话回顾与再评估

- 保存问诊记录、量表记录、多模态记录、临床决策结果、干预执行记录和用户反馈。
- 形成时间线式历史追踪记录和事件化再评估信息。
- 如需要再次筛查，则回到“问诊准备”进入下一轮闭环。
