# `assessment_answers` 表说明

## 1. 表作用

`assessment_answers` 用来保存量表作答过程中的逐题答案明细。每答完一题，就会新增一条记录。

这张表对应量表域里的“原始作答事实”，是后续计分、复核、回放和多模态对齐的基础。

## 2. 在系统哪一步使用

1. 逐题作答：用户提交单题答案后立即写入本表。
2. 归一化处理：把用户原始输入归一化成量表选项标签和数值分数。
3. 单量表计分：每份量表完成时，读取当前量表在本表中的所有答案进行得分计算。
4. 多模态关联：`capture_timestamp` 可用于和音视频片段、传感器时间轴做对齐。

## 3. 字段说明

| 字段名 | 英文翻译 | 中文翻译 | 类型/约束 | 作用 | 为什么需要这个字段 | 主要使用步骤 |
| --- | --- | --- | --- | --- | --- | --- |
| `id` | Assessment Answer ID | 量表答案ID | `String(36)`，主键 | 唯一标识一条题目答案记录。 | 单题答案需要独立标识，便于追踪、排障和后续扩展。 | 单题提交 |
| `session_id` | Assessment Session ID | 量表会话ID | `String(36)`，外键到 `assessment_sessions.id`，索引，非空 | 指明这条答案属于哪次量表会话。 | 没有会话外键就无法将多题答案聚合回一场评估。 | 单题提交、计分 |
| `scale_slug` | Scale Slug | 量表标识 | `String(128)`，索引，非空 | 标识这条答案属于哪一份量表。 | 一场量表会话可能包含多份量表，必须明确答案归属。 | 单题提交、分量表计分 |
| `item_id` | Item ID | 题目ID | `String(128)`，非空 | 标识量表中的具体题目。 | 同一量表内的题目必须可唯一定位，才能防止重复提交和错题作答。 | 单题提交、重复校验 |
| `item_index` | Item Index | 题目序号 | `Integer`，非空 | 标识题目在量表中的顺序位置。 | 计分、回放和调试时经常需要顺序号，不能只依赖字符串题目ID。 | 单题提交、计分排序 |
| `raw_input` | Raw Input | 原始输入 | `Text`，可空 | 保存用户提交前的原始文本输入。 | 语音转文字或自由文本输入可能含歧义，保留原文便于复核归一化过程。 | 单题提交、异常排查 |
| `normalized_option` | Normalized Option | 归一化选项 | `String(255)`，非空 | 保存系统最终识别出的标准选项标签。 | 原始回答可能是数字、短语或模糊文本，必须归一到标准选项后才能可靠计分。 | 归一化、计分 |
| `score_value` | Score Value | 分值 | `Integer`，非空 | 保存该题最终采用的数值分数。 | 下游计分逻辑直接依赖数值分，不应每次再从文本推断。 | 单题提交、计分 |
| `capture_timestamp` | Capture Timestamp | 采集时间戳 | `DateTime(timezone=True)`，可空 | 记录用户作答发生的采集时间。 | 多模态服务若要对齐表情、语音、视频片段，需要一个尽量贴近采集时刻的时间点。 | 单题提交、多模态关联 |
| `created_at` | Created Time | 落库时间 | `DateTime(timezone=True)`，非空 | 记录该答案写入数据库的时间。 | 需要知道服务端实际接收并落库的时刻，用于审计和时序排查。 | 单题提交、审计 |

## 4. 备注

- 表上存在唯一约束 `session_id + scale_slug + item_id`，用来防止同一题被重复提交。
- 这张表保存的是“逐题事实”，并不直接保存量表总分；总分保存在 `assessment_results`。
