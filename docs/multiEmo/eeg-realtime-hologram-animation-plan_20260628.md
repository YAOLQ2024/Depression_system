# EEG 实时 3D 全息头模动画改造方案

更新时间：2026-06-28

适用仓库：`depression-system`

适用范围：

- `apps/consultation/client`
- `docs/multiEmo`

替代说明：

1. 本文替代当前“位图主视觉切换”方向。
2. 本文用于解决“像静态图片”“三导联点不呼吸”“网络无实时动画”“不同表情切换割裂”四类核心问题。
3. 后续 EEG 右侧视觉区如继续重构，应以本文为主方案。

---

## 1. 结论先行

当前右侧 EEG 主视觉如果继续使用：

- `png/svg` 整图切换
- `img` 交叉淡入淡出
- 每种情绪一整张独立头模图

那么无法同时满足以下四个目标：

1. 看起来像“实时 3D 建模图像”，而不是一张静态海报。
2. 三个导联点位具备真实呼吸光和脉冲节律。
3. 网络粒子、连线、能量扩散具备可持续的动画感。
4. 三种情绪切换时头模完全对齐，没有脸型跳动和割裂感。

因此，这次不应继续优化“图片素材”，而应把右侧 EEG 区从：

**图片切换组件**

升级为：

**统一坐标系的全息头模动态图层组件**

---

## 2. 当前实现问题拆解

## 2.1 为什么现在会像“图片”

当前实现本质上是：

- 一张整图作为主视觉
- 根据情绪替换图片
- 再叠少量外层 UI 装饰

这会导致：

1. 头模内部所有亮点、线条、粒子、导联点都是“固化”的。
2. 即使外层做一点淡入淡出，也还是静态图切换，不像实时建模。
3. 图像内部没有独立可控的节点节律、粒子路径和局部能量变化。

一句话总结：

**当前不是“模型在动”，而是“图片在换”。**

## 2.2 为什么三导联点做不好

如果三导联点是画在整张位图里的，那么：

1. 只能整体一起亮或一起暗。
2. 不能做独立呼吸频率。
3. 不能做节点外圈扩散和脉冲层级。
4. 不能保证与后续粒子流动方向严格对应。

## 2.3 为什么切换会割裂

当前三种情绪的头模来自三张独立图。

哪怕构图很接近，也一定会出现：

1. 脸型轮廓轻微变化
2. 五官位置轻微偏移
3. 节点坐标不完全重合
4. 粒子和线条起点不一致

因此切换时会有明显“跳图感”。

## 2.4 为什么“继续调图片”不是正解

继续优化位图，只能改善：

- 风格像不像
- 光感好不好
- 色彩够不够高级

但无法从根本上解决：

- 实时感
- 呼吸光
- 连续动画
- 几何对齐

---

## 3. 需求重新定义

根据最新要求，右侧 EEG 区的新目标不是“更好看的一张图”，而是：

## 3.1 主目标

1. 看起来像实时 3D 全息建模头模。
2. 三个导联点位固定且可呼吸发光。
3. 网络粒子、连线、能量流具备持续动画。
4. 情绪变化主要通过网络行为变化表达，而不是通过整张图替换表达。
5. 头模本体必须始终对齐，切换不能跳。

## 3.2 可接受边界

可以不是“真 3D WebGL 模型”，但必须达到：

- **像实时 3D 建模监测面板**

而不是：

- 插画
- 静态海报
- 切图幻灯片

---

## 4. 可行性分析

## 4.1 能不能实现

可以实现。

但前提是改变实现方式。

## 4.2 不推荐的路线

### 路线 A：继续用整张 PNG/位图

不推荐原因：

1. 无法做节点独立呼吸光。
2. 无法做真实网络粒子流。
3. 无法消除不同情绪图之间的几何错位。
4. 只能做“切图动画”，不能做“模型动画”。

### 路线 B：直接上 Three.js 真 3D

理论可行，但当前阶段不推荐作为第一实现。

原因：

1. 工程复杂度明显上升。
2. 需要额外的几何资源、材质、后处理。
3. 在当前仪表盘小面板内，投入产出比不高。
4. 当前需求更像“全息 3D 视觉模拟”，不是真的要 360° 交互模型。

## 4.3 推荐路线

推荐采用：

**SVG + Canvas + CSS/Motion 的混合图层方案**

原因：

1. 可精确控制统一坐标系。
2. 可保证三导联点永久固定。
3. SVG 适合头模轮廓、网格、路径、节点、能量环。
4. Canvas 适合粒子流动和稠密点云闪烁。
5. CSS/Motion 适合呼吸光、柔和漂移、状态过渡。
6. 不需要引入真正的 3D 引擎，也能做出“像实时建模”的视觉感。

## 5. 新架构方案

## 5.1 总体思路

右侧 EEG 面板从单张图片改为五层结构：

1. 背景层
2. 头模结构层
3. 导联节点层
4. 网络与粒子层
5. 底部标签与百分比层

其中：

- 头模结构层始终不换坐标系
- 三导联点始终不换位置
- 情绪切换只改变颜色、亮度、粒子数量、流动方向、线条连续性、节点光效

## 5.2 推荐组件结构

建议新增或重构为以下结构：

- `EegHologramPanel`
- `EegHeadMeshLayer`
- `EegLeadNodeLayer`
- `EegNetworkLayer`
- `EegParticleFieldLayer`
- `EegPedestalLayer`
- `eegHologramGeometry.ts`
- `eegHologramTokens.ts`
- `useEegHologramAnimation.ts`

## 6. 统一几何原则

这是解决切换割裂的关键。

## 6.1 只允许一套头模几何

三种情绪必须共用：

1. 同一个头部外轮廓
2. 同一套面部线框
3. 同一套点云分布
4. 同一套三导联节点坐标
5. 同一套基准网络路径集合

换言之：

**头模不换，状态在头模之上变化。**

## 6.2 表情差异必须最小化

为了避免脸跳动：

1. 不再使用三张不同的人脸图。
2. 表情差异只允许体现在极小范围的嘴角和眼睑线条上。
3. 这类差异也必须在同一坐标系内微调，不得整体挪脸。

更稳妥的做法是：

**弱化表情差异，强化网络行为差异。**

这更符合 EEG 可视化逻辑，也更不容易割裂。

## 7. 三导联点设计方案

## 7.1 点位位置

三导联点统一固定在头模坐标系中：

1. 左颞叶：头部左上外侧
2. `Fpz`：前额中央偏上
3. 右颞叶：头部右上外侧

无论任何情绪态，三点坐标完全不变。

## 7.2 节点层级

每个导联点建议拆成四层：

1. 中心亮点
2. 内环
3. 外环
4. 外扩柔光

## 7.3 呼吸光动画

三个点位都改为呼吸光。

推荐节律：

1. `Fpz` 呼吸幅度最大
2. 左右颞叶呼吸幅度略低
3. 三点可同相，也可 `Fpz` 轻微提前 `120ms ~ 180ms`

推荐动画内容：

1. 核心亮点明暗交替
2. 外环缓慢扩张再回收
3. 柔光层透明度轻微起伏
4. 在高兴态可增加更强的节点晕光

---

## 8. 头模“实时 3D 建模感”设计

## 8.1 视觉语言

头模应模拟：

- 点云建模
- 线框建模
- 全息扫描
- 深色背景上的自发光模型

## 8.2 头模结构建议

头模本体建议由以下元素叠加：

1. 外轮廓亮线
2. 面部等高线
3. 纵向扫描线
4. 稠密点云
5. 少量深度参考弧线
6. 颈部能量下垂线
7. 底部环形基座

## 8.3 为什么这会比位图更像“实时建模”

因为“实时感”来自：

1. 点云闪烁
2. 细线轻微漂移
3. 局部脉冲
4. 粒子流动
5. 节点扩散
6. 能量环缓慢呼吸

只要这些细节是实时生成或实时动画的，就会比一张图更像“建模图像”。

---

## 9. 三种情绪态动画规则

## 9.1 蓝色悲伤态

设计目标：

- 网络粒子少
- 流动慢
- 线条轻微断续
- 整体有下沉感

具体建议：

1. 粒子数量最低
2. 粒子速度最慢
3. 连线使用较长间隔的 `dash` 效果
4. 某些支线路径透明度周期性衰减
5. 全局网络重心略向下
6. 头模下方垂落能量线更明显
7. 蓝色态整体亮度最低

视觉感受：

**冷、收缩、缓慢、略下坠**

## 9.2 黄色平静态

设计目标：

- 脉冲均匀
- 连接线稳定
- 光环扩散柔和

具体建议：

1. 粒子数量中等
2. 粒子速度中等偏慢
3. 连线保持完整稳定
4. 节点呼吸节律最平稳
5. 基座能量环扩散最柔和
6. 头模整体无明显上下偏移

视觉感受：

**平衡、匀速、稳定、克制**

## 9.3 绿色高兴态

设计目标：

- 粒子更多
- 线条更连贯
- 光从 `Fpz` 向双颞叶扩散
- 整体有向上感

具体建议：

1. 粒子数量最多
2. 粒子速度最快
3. 主连线路径最亮、最连续
4. `Fpz` 发光最强，粒子从 `Fpz` 向左右扩散
5. 头模上半部光感更强
6. 竖向粒子和外围细光线有轻微上扬感
7. 基座中心能量柱更强

视觉感受：

**通透、扩张、向上、协同增强**

## 10. 动画实现建议

## 10.1 推荐动画技术分工

### SVG 负责

1. 头模轮廓
2. 面部线框
3. 节点与外环
4. 网络基准路径
5. 基座能量环

### Canvas 负责

1. 沿路径流动的粒子
2. 点云闪烁
3. 稀疏/稠密动态粒子分布
4. 轻微深度噪声

### CSS / Motion 负责

1. 呼吸光
2. 节点光晕
3. 状态颜色过渡
4. 全局轻微上下漂移
5. 面板整体淡入淡出

## 10.2 为什么不建议全部靠 CSS

纯 CSS 可以做：

- 呼吸光
- opacity 起伏
- 柔和缩放

但不擅长：

- 大量粒子沿路径连续流动
- 不同情绪下粒子密度和速度差异
- 断续线条的自然动态

因此推荐混合方案。

## 10.3 动画刷新方式

建议：

1. SVG 结构层静态渲染
2. 粒子层使用 `requestAnimationFrame`
3. 状态变化通过 React state + CSS variables 驱动

这样可避免每帧整棵 React 树重渲染。

## 11. 状态切换策略

## 11.1 不再整图切换

后续禁止以下逻辑作为主方案：

- 蓝图 -> 黄图 -> 绿图 之间整张 `img` 交叉淡入淡出

应该改为：

- 同一头模不动
- 颜色过渡
- 节点节律改变
- 粒子数变化
- 线路透明度和连续性变化
- 流动方向变化

## 11.2 切换时长

推荐整体状态过渡时长：

- `320ms ~ 520ms`

其中：

1. 颜色最先变化
2. 呼吸光在 `120ms` 内同步到新态
3. 粒子密度和速度在 `300ms ~ 500ms` 内缓变
4. 全局上扬/下沉位移缓慢过渡

## 11.3 稳定性策略

建议主情绪切换增加轻微迟滞，避免频繁跳态：

1. 新主类显著高于当前主类再切
2. 或连续两帧一致再切

这样动画会像监测面板，而不是像闪烁灯牌。

## 13. 风险与注意事项

## 13.1 最大风险

最大的风险不是性能，而是：

**做成“很多会动的装饰”，但仍然不像一个统一的实时头模。**

所以必须坚持：

1. 一套统一几何
2. 一套统一导联点坐标
3. 动画围绕“网络行为”展开
4. 不堆砌无意义粒子

## 13.2 性能风险

若粒子过多，可能影响低性能设备。

建议：

1. Canvas 粒子数量设置上限
2. 面板尺寸较小时自动降采样
3. `prefers-reduced-motion` 下退化为低动画强度版本

## 13.3 风格风险

如果头模表情变化太大，会重新引入割裂。

因此：

- 表情只能微调
- 情绪感主要靠网络状态表达

## 14. 分阶段实施建议

## 14.1 第一阶段

目标：

- 先摆脱整图切换
- 建立统一头模几何

内容：

1. 用统一 SVG 头模替代三张独立图
2. 固定三导联点坐标
3. 实现节点呼吸光

## 14.2 第二阶段

目标：

- 补全全息感和实时感

内容：

1. 增加头模点云闪烁
2. 增加基座能量环
3. 增加背景轻网格与扫描感

## 14.3 第三阶段

目标：

- 完成情绪网络行为差异

内容：

1. 增加粒子沿路径流动
2. 增加蓝/黄/绿三态的密度、速度、方向差异
3. 增加 `Fpz` 扩散与全局上扬/下沉感

## 14.4 第四阶段

目标：

- 优化切换连续性

内容：

1. 状态过渡节律统一
2. 切换迟滞
3. 减少闪烁和噪声

---

## 15. 验收标准

达到以下条件可视为方案成功：

1. 右侧主视觉不再像整张静态图片。
2. 三导联点固定不跳，并具有明显呼吸光。
3. 头模始终对齐，切换没有脸型错位。
4. 蓝色态粒子更少、流动更慢、连线有轻微断续、整体下沉。
5. 黄色态脉冲均匀、连线稳定、光环扩散柔和。
6. 绿色态粒子更多、线条更连贯、光从 `Fpz` 向双颞叶扩散，并有向上感。
7. 整体看起来像实时 EEG 全息建模面板，而不是切换图片。

---

## 16. 一句话总结

这次右侧 EEG 可视化不该继续优化“图片素材”，而应改造成**同一头模几何下、以三导联呼吸光和情绪网络动画为核心的实时全息头模组件**；只有把“位图切换”升级为“统一坐标系动态图层”，才能同时满足实时 3D 建模感、导联点呼吸光、情绪网络动画和无割裂切换这四个目标。
