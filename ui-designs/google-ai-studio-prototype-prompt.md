# MCS Consultation UI Prototype Prompt

## 一、项目流程梳理

### 1. 项目定位

`MCS` 是 `Multimodal Consultation System`。患者侧主应用是 `apps/consultation`，它不是普通展示站，而是承接完整问诊主链的前台应用。

当前仓库的关键组成：

- 前端应用：
  - `apps/consultation`：患者侧问诊主链
  - `apps/operations-console`：运营/管理侧
- 后端服务：
  - `gateway-service`：浏览器侧 BFF，负责认证代理、bootstrap 聚合、问诊/量表接口转发
  - `identity-service`：用户与患者档案
  - `consultation-service`：规则版数字人问诊状态机
  - `assessment-service`：量表问诊、计分与聚合结果
  - 后续还有 `risk-service`、`intervention-service`、`followup-service`、`multimodal-service`、`ai-service`

### 2. 患者侧业务主流程

患者侧目标流程是：

1. 登录 / 注册
2. 问诊准备
3. 创建问诊会话
4. 数字人交互问诊
5. 量表问诊
6. 临床决策结果
7. 调节干预
8. 回顾与再评估

其中数字人问诊是固定主链，不是自由聊天：

- 初始问候与流程说明
- 主诉采集
- 现病史规则式问诊
- 高风险问题排查

为了提升前端可理解性，UI 可以把数字人问诊细分成 6 个可视步骤：

1. 主诉采集
2. 现病史
3. 睡眠饮食
4. 情绪体验
5. 高风险筛查
6. 总结建议

量表问诊阶段当前固定 4 个量表：

- `PHQ-9`
- `SDS`
- `SAS`
- `SDSS`

### 3. 当前实际实现边界

当前 `apps/consultation/client` 已经是 `React + TypeScript + Vite`，并且已经存在这些真实页面状态：

- 未登录：登录 / 注册页
- 已登录但档案未完成：问诊准备页
- 档案完成未开始问诊：正式问诊入口页
- 问诊会话进行中：数字人问诊页
- 量表会话进行中：量表问诊页

当前前端已经对接或预留了这些接口：

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `GET /api/v1/users/me`
- `PUT /api/v1/users/me/profile`
- `GET /api/v1/system/bootstrap`
- `POST /api/v1/consultations`
- `GET /api/v1/consultations/{id}`
- `POST /api/v1/consultations/{id}/start`
- `POST /api/v1/consultations/{id}/turns`
- `GET /api/v1/assessment/catalog`
- `POST /api/v1/assessment/sessions`
- `GET /api/v1/assessment/sessions/{id}`
- `POST /api/v1/assessment/sessions/{id}/answers`

### 4. 这次 UI 原型的目标

这次不是做纯视觉稿，而是做一版“可运行的高保真原型”，后续需要接回现有项目。因此原型必须满足：

- 风格高度参考我提供的三张 UI 图
- 页面结构贴合现有患者侧流程
- 技术形态适合后续接入 `apps/consultation/client`
- 先用 mock data 和本地状态完成原型，不直接写死后端耦合逻辑
- 保留明确的组件边界、状态边界和后续 API 接入点
